# 局域网本地模型跨机器部署

目标：Web / Portal 跑在同事的服务器上；本地模型（ComfyUI + AI Port）仍跑在模型机（你的电脑）上。浏览器只访问服务器，服务器再用 Python 服务端方式去调模型机，因此同事的浏览器不需要直接连模型机。

## 一、模型机（跑本地模型的 Windows）

本机已经完成以下配置，换机器时按同样方式重做。

### 1. AI Port 监听所有网卡

设置持久化环境变量：

```powershell
setx LOCAL_AI_LISTEN "0.0.0.0"
```

`local_ai_backends_watchdog.ps1` 会读取它：AI Port 监听 `0.0.0.0:8801`，ComfyUI 仍只监听 `127.0.0.1`。修改后需要重启 AI Port 才生效。

验证：

```powershell
Get-NetTCPConnection -LocalPort 8801 -State Listen
```

应看到 `LocalAddress` 为 `0.0.0.0`。

### 2. 防火墙放行 8801

已创建并启用入站规则 `AI Port 8801 LAN`。换机器时执行：

```powershell
New-NetFirewallRule -DisplayName "AI Port 8801 LAN" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8801
```

### 3. 用主机名而不是 IP

服务器端默认地址是：

```text
http://UT-20210713KMWD.local:8801
```

`.local` 走 mDNS，Windows 和 macOS 都支持，所以模型机 IP 每周变化不影响。

如果局域网内 `.local` 解析不通（部分路由器会关 mDNS），改用路由器给模型机绑定静态 IP，然后把下面服务器端的 `AIPORT_BASE_URL` 改成 `http://固定IP:8801`。

## 二、服务器（同事部署 Web）

通用 clone / venv / 依赖步骤见 [clone-and-run.md](clone-and-run.md)。

服务器端不需要本地模型，只需要让各 Python 后端知道去哪里找模型机：

```powershell
# Windows
setx AIPORT_BASE_URL "http://UT-20210713KMWD.local:8801"
```

```bash
# macOS / Linux
export AIPORT_BASE_URL="http://UT-20210713KMWD.local:8801"
```

`Start All.bat`、`Start All.command`、`portal_watchdog.ps1`、`deploy/ai-portal.service` 已经内置这个默认值，一般不需要额外设置；直接启动 Portal 即可：

```bash
cd portal
python3 app.py
```

Portal 默认监听 `0.0.0.0:9090`，同事浏览器访问 `http://服务器IP:9090`。

## 三、兜底行为

- Nano Banana 默认 `t8star`，Seedance 默认 `volcengine`，导演台默认 Ark 云端 `doubao-seedream-5-0-pro-260628`。
- 后端启动时会探活 `AIPORT_BASE_URL/api/modules`。探活成功才使用 `comfyui_local`；失败时默认模型自动回云端。
- 前端若手动切换到「本地 ComfyUI」，但本地不可用，会提示并自动恢复到当前云端模型，避免提交到不存在的本地网关。

## 四、快速排查

在服务器上验证模型机连通性：

```bash
curl http://UT-20210713KMWD.local:8801/api/modules
```

- 返回 JSON 表示服务器到模型机通了。
- 超时或拒绝连接：检查模型机 AI Port 是否监听 `0.0.0.0:8801`、防火墙 8801 是否放行、`.local` 是否可解析。
- `.local` 解析不到：改用路由器静态 IP，并同步改 `AIPORT_BASE_URL`。
- 忘记设置 `AIPORT_BASE_URL` 时，后端会默认找 `127.0.0.1:8801`，导致只找服务器本机；确保服务器端环境变量已生效后再启动 Portal。

## 五、模型机运行注意事项

1. 保持这台电脑开机、不睡眠、不断网，AI Port 和 ComfyUI 要一直在运行；你关机或睡眠后，同事那边会自动回云端，但本地模型就用不了了。
2. 让所有同事、服务器和模型机在同一个局域网/网段，并关闭路由器里的“AP 隔离 / 客户端隔离”，否则 `.local` 和 `8801` 可能被阻断。
3. `8801` 只对内网放行，不要转发到公网；如果这台机器有公网 IP，尤其不要把 8801 暴露出去。
4. 多人同时调用会并发打到你的显卡和内存，视频生成更吃资源；必要时限制 AI Port 并发，或提醒同事错峰。
5. 生成图片/视频会占用你的磁盘和上行带宽，定期清理 ComfyUI/AI Port 的临时上传和 `outputs`。
6. 如果某天 `.local` 解析不了，用路由器给模型机绑定静态 IP，并把服务器端 `AIPORT_BASE_URL` 改成 `http://固定IP:8801`。
7. 别在同事正在调用时重装/更新 ComfyUI、切换模型文件或重启模型机，否则正在跑的任务会中断。
8. 换模型机时，`local_ai_backends_watchdog.ps1` 里的 `ComfyRoot` 是本机绝对路径，需要同步改成新机器的 ComfyUI 路径。

## 六、已具备的自动保护

- 自动重启：`local_ai_backends_watchdog.ps1` 每 5 秒探活 ComfyUI `8188` 和 AI Port `8801`，进程退出或健康检查失败会自动拉起，无需人工值守。
- 排队策略：AI Port 默认 `AI_PORT_RUN_SLOTS=1`，一次只占一个 GPU 运行槽，其他任务排队；同时限制 `AI_PORT_MAX_ACTIVE_JOBS=100` 个活动任务，超过会拒绝而不是把机器打崩。
- 自动清理：AI Port 有自己的运行期清理器，会按 `AI_PORT_JOB_TTL_SECONDS` 和 `AI_PORT_FILE_TTL_SECONDS` 定期清理过期任务记录和文件，无需手动盯。
- 模型清理：ComfyUI 的未引用模型清理目前是手动脚本 `Run_Model_Cleanup.cmd`，不放入自动清理，避免误删正在使用的模型。
- IP 变化：服务器端用主机名 `UT-20210713KMWD.local`，模型机 IP 每周变也不影响；只有 mDNS 被路由器禁用时才需要改用静态 IP。
