# 公网部署迁移方案（easyq.cn）

> 2026-08-20 定稿。目标：整套后端从用户 Mac 迁到云服务器，同事经 `https://easyq.cn` 访问。
> 状态：方案已定，外部步骤（备案/采购）由用户执行，其余产物在 `deploy/`。

## 0. 决策记录

| 决策点 | 结论 |
|---|---|
| 部署形态 | 整套搬到服务器（Mac 退出生产，保留为开发/备用机） |
| 域名 | easyq.cn，DNS 托管在火山引擎（NS: vip1/vip2.volcengine-dns.com），当前 A 记录 198.18.3.53 为占位值，上线前改指服务器 IP |
| 开放注册 | 关闭（复用既有 `signup_enabled` 开关，**零代码改动**） |
| 备案 | 用户待查（2026-08-20） |
| TLS | Caddy 在服务器终结（Let's Encrypt 自动签发/续期），Portal 以 `PORTAL_HTTP_ONLY=1` 跑纯 HTTP |

## 1. 目标架构

```
同事浏览器
   │  https://easyq.cn:443
   ▼
Caddy（easyq.cn → 127.0.0.1:9090，自动 HTTPS + http→https 跳转）
   ▼
Portal app.py（PORTAL_HTTP_ONLY=1，9090）
   ├── /seedance/* ──→ seedance fastapi（uvicorn，内网端口）
   ├── /nano-banana/* ──→ nano-banana fastapi
   ├── /dreamina/* ──→ dreamina fastapi + dreamina CLI
   ├── /volcengine-portrait/* / 无限画布 / 飞书 agent 同构
   └── 统计 / 用量登记（X-Job-Id 链路，逻辑不动）
```

安全组只开 **22 / 80 / 443**；9090 与子应用端口只在服务器本机可达（ufw 第二层）。

### 代码侧已有开关（本方案零代码改动的依据）

| 能力 | 位置 |
|---|---|
| `PORTAL_HTTP_ONLY=1` 纯 HTTP 模式（TLS 上游终结） | `portal/app.py:2246-2249` |
| `_is_https()` 信任 `X-Forwarded-Proto`（Caddy 自动带） | `portal/app.py:1352-1355` |
| `ALLOWED_ORIGINS` 环境变量覆盖 CORS 白名单 | `portal/app.py:94-102` |
| `signup_enabled` 注册开关（users.json + admin API `/api/auth/signup-toggle` + 登录页自动隐藏注册入口） | `portal/app.py:390-397, 1484-1493, 1590-1592` |

## 2. 服务器选型（建议，以控制台实时价为准）

> **2026-08-20 实际购入**（火山引擎大陆节点，IP `124.174.33.130`，SSH 别名 `easyq`）：
> 4核16G / 单盘 200G / Ubuntu 22.04.4 LTS / 时区待设 Asia/Shanghai。
> 与建议的偏差：22.04 无自带 python3.12 → `init-server.sh` 已加 deadsnakes PPA 分支；16G 内存比建议的 8G 更宽裕。
> **备案状态待用户确认（决策门）**：大陆节点 80/443 依赖备案；未备案则走备案流程（1-4 周）或换香港节点。

- **规格**：4C8G；系统盘 40G ESSD + 数据盘 100G；Ubuntu 24.04 LTS（自带 python3.12）
  - 8G 内存理由：下载链路是双层整读（50-200MB 视频 ×并发 ×2 份，见 CLAUDE.md 已知瓶颈）+ 6 个 uvicorn + Portal 主进程
- **带宽**：按使用流量（峰值 50-100M）或固定 10M。同事下长视频，带宽是体感瓶颈
- **地域两路径**：
  - **香港（免备案，本周可上线）**：域名解析到 HK IP 即可。Ark/DeepSeek/飞书 API 均可达；待验证项：即梦 dreamina CLI 从 HK 的连通性（Phase 5 第一项）
  - **大陆（北京等，需备案 1-4 周）**：延迟最低、流量便宜；备案完成前 80/443 不对外服务
- **时区**：`timedatectl set-timezone Asia/Shanghai`（飞书日报调度依赖本地时间）
- **备案查询**：工信部 beian.miit.gov.cn →「备案信息查询」输 easyq.cn；或火山引擎控制台 → 域名与网站 → 备案。大陆服务器 + 未备案域名 = 80/443 被拦，硬门槛

## 3. 搬迁步骤（Phase）

### Phase 1 外部（用户）
1. 查备案（上节步骤）
2. 按备案结果买服务器（HK 或大陆）
3. 服务器控制台安全组开 22/80/443（先只放自己 IP 的 22）
4. **DNS 先不动**——内网 IP 验证完再切（§Phase 5 之后）

### Phase 2 服务器初始化（`deploy/init-server.sh`，幂等）
- apt 装 python3.12(+venv)/git/rsync/curl/ufw
- Caddy（官方源，systemd 托管）
- 仓库根 `.venv` + `pip install -r requirements.txt`（portal 经 `.venv/bin/uvicorn` 拉起子应用，venv 必须在仓库根）
- feishu-generation-agent 独立 `.venv` + `pip install -e .`（pyproject 装 `feishu_generation_agent==0.1.0`，依赖 langchain/anthropic/lark_channel_sdk/sqlite_vec 等）
- **dreamina CLI 的 Linux 版**：Mac 上是 Go 二进制（bytedance/cloudwego 系），来源待用户确认（Mac 版从哪下载的，同页应有 linux-x64）
- ufw 白名单 22/80/443

### Phase 3 代码+数据搬迁（`deploy/sync-data.sh`，Mac 上执行）
rsync 全量（约 7G，`--partial` 可断点续传）：
- **排除**：`.git`、`.venv`、`feishu-generation-agent/.venv`、`state/workspaces`（草稿缓存，seedance 9.1G + nano-banana 7.7G，按 2026-07-22 先例可弃）、`logs`、`state/certs`、`portal/state/portal.pem|key`、`release/`、`__pycache__`
- **必搬**：各 app `state/`（users/usage/sessions/user_keys/feishu/activity_log——**统计数据全在这**）、`archives/`（预设，可能含 API key）、`dreamina/accounts/`（即梦登录态 23M）、各 `outputs/`（用户产出 ~2G）、`uploads/`、`feishu-output-sync/config.json`（gitignored）
- 已知可接受损失：旧 `download_files.json` 里绝对路径 token 失效（下载 token 本就短命）

### Phase 4 服务化（`deploy/*.service` + `deploy/Caddyfile`）
- `ai-portal.service`：环境变量复刻 Mac plist（`*_ENGINE=fastapi`、`PORTAL_HTTP_ONLY=1`、`ALLOWED_ORIGINS=https://easyq.cn`、`PORTAL_PORT=9090`）；`KillMode=control-group` 重启时连子 uvicorn 一起收；DYLD_LIBRARY_PATH 是 macOS 专属，Linux 不要
- `feishu-generation-agent.service`（8765）、`feishu-output-sync.service`
- Caddyfile：`easyq.cn → 127.0.0.1:9090`、`www` 重定向、`request_body max_size 2GB`（大视频上传）

### Phase 5 端到端验证（IP 直连，DNS 未切）
- [ ] 登录/注销、注册入口已隐藏（signup_enabled=false）
- [ ] **dreamina CLI 连通性**（HK 场景第一优先验证）
- [ ] 每个子应用真跑一单：seedance / nano-banana / dreamina / 人像 / 无限画布 / 飞书 agent（live 实测，允许少量出图费——CLAUDE.md 核心原则）
- [ ] **统计链路**（！！！核心）：提交任务 → `usage.json` 计数 +1 → `activity_log.json` 落笔 → `X-Job-Id` 头登记未被代理层吃掉
- [ ] 下载（blob 链路）、视频 Range/首帧、无限画布 TOS 预签名、素材库、ComfyUI 工作流
- [ ] 飞书产出搬运（output-sync）落到多维表格
- [ ] Let's Encrypt 证书签发成功、续期 cron 就位
- [ ] 大文件上传/下载走 Caddy 的稳定性与内存（监控 `/var/log/ai-portal/`）

### Phase 6 切换
1. 火山引擎云解析：easyq.cn A 记录（@、www）→ 服务器 IP
2. Mac 侧 `launchctl unload` 三个生产 plist（**必须**：双活会把统计劈成两半）
3. 服务器 `signup_enabled=false`（rsync 时可能已带过来，核对即可）
4. 大陆部署若备案完成：页脚挂备案号（法定义务）

## 4. 风险与回滚

| 风险 | 应对 |
|---|---|
| 即梦 CLI / 其他国内 API 从 HK 连通差 | Phase 5 第一个验证；不通则改大陆+备案路径 |
| rsync 7G 走家用上行 | 非高峰时段跑，`--partial` 续传 |
| 切换窗口统计分裂 | DNS 切完立刻停 Mac 生产（同一步执行） |
| 大视频下载内存（已知双层缓冲瓶颈） | 8G 内存兜底；出现 OOM 再流式化（有历史尝试记录，见 CLAUDE.md） |
| 回滚 | DNS 指回 Mac 公网 IP + Mac plist 恢复加载（Mac 端数据保留不动，天然备份） |
