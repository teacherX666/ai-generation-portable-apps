# 前端上手优化建议

> 文档版本：2026-09-01  
> 目标：让新实习生第一次打开平台时，不需要翻手册或问人，也能在几分钟内完成第一个任务；同时降低后续加模块、改交互时的维护成本。

## 1. 当前最值得先解决的问题

当前功能已经很完整，主要问题不是“缺能力”，而是“新手找不到入口、不知道下一步做什么”。

建议优先级：

| 优先级 | 方向 | 预期效果 |
|---|---|---|
| P0 | 增加新人引导和模块内帮助 | 新用户第一次进入就有明确路径 |
| P0 | 修正移动端模块入口缺失 | 移动端和桌面端看到的模块一致 |
| P0 | 顶部导航重新分组 | 11 个入口不再全部平铺 |
| P0 | 统一反馈和防误操作 | 减少 alert/confirm/prompt，降低误点成本 |
| P1 | 增强跨模块产出库和复用能力 | 用户不再在多个模块里找结果 |
| P1 | 任务排队位置和预计时间 | 视频生成等待期不再黑盒 |
| P1 | 密钥一键应用到子应用 | 减少手动复制和“密钥库为什么没用”的困惑 |
| P2 | 拆分 Portal 前端巨石文件 | 便于新同学接手和多人并行修改 |

## 2. 当前代码中的具体观察

### 2.1 没有新手引导和帮助入口

在 `portal/static` 中搜索 `onboarding`、`guide`、`help`、`新手`、`教程`、`tooltip` 等关键词，没有面向业务模块的引导系统。

现状：

- 新用户登录后直接进入 Seedance。
- 没有“第一次先配置什么”的提示。
- 没有帮助按钮。
- 各个模块的空状态多数只显示“暂无内容”，没有建议下一步。

建议：

1. 在顶栏加一个固定“帮助 / 新手指南”按钮。
2. 首次登录显示一个可关闭的 5 步检查清单：

   ```text
   1. 检查我的 API Key
   2. 跑一张测试图
   3. 跑一个测试视频
   4. 查看历史记录
   5. 了解报错助手
   ```

3. 每个模块顶部放一个轻量上下文帮助条：

   - 这个模块适合做什么
   - 第一次操作分 3 步
   - 结果会出现在哪里

4. 不要整段说明文字常驻页面。建议用“帮助图标 + 悬浮提示 + 可展开抽屉”，只在对应用户需要时出现。

### 2.2 移动端下拉框漏掉了“分镜布局”

桌面端标签栏包含：

```text
Seedance / 图像生成模块 / 飞书任务 Agent / Dreamina / 人像生成 /
无限画布 / 分镜布局 / 密钥库 / 报错问答助手 / 历史记录 / 统计
```

移动端 `mobileAppSelect` 的选项没有“分镜布局”，见：

- `portal/static/index.html:28-40`

移动端还会隐藏桌面标签栏：

- `portal/static/styles.css:1295`

这导致移动端和桌面端功能入口不一致。

建议：

1. 从同一个注册表生成桌面标签和移动端下拉框，而不是各写一份。
2. 至少先补上“分镜布局”选项，并明确提示 WebGL2/3D 功能建议桌面使用。
3. 对不适合移动端的模块不要隐藏，而是保留入口并给出明确原因。

### 2.3 顶部入口已经偏多

当前桌面端有 11 个顶级标签：

- `portal/static/index.html:43-53`

所有入口平铺，会稀释主要工作流。

建议：

```text
创作区：
Seedance / 图像生成 / 飞书任务 Agent / 人像生成 / 无限画布 / 分镜布局

协作与查询区：
Dreamina / 历史记录 / 报错问答助手

个人与管理区：
密钥库 / 统计
```

实现方式：

- 桌面端用两个分区加一个“更多”。
- 使用频率低的模块可放入“更多工具”。
- 保留快捷键或搜索入口，例如 `Ctrl/Cmd + K` 打开模块搜索。
- 默认首屏不一定是 Seedance，可以由“最近使用”决定，或显示一个轻量的“创作入口页”。

注意：Dreamina 当前使用频率明显低于其他主力模块，适合归入“更多工具”或二级入口，而不是继续和 Seedance、图像生成平级。

### 2.4 模块注册表已经存在，但前端标签仍是手写

后端已有 `portal/apps.json`，并由 Portal 向 `/api/apps` 暴露：

- `portal/apps.json`
- `portal/static/app.js:244-279` 已根据配置注入部分 iframe

但顶部按钮、面板 ID、移动端下拉框仍然是手写。

当前新增一个子应用时，需要同时改：

1. `apps.json`
2. 桌面端 tab 按钮
3. tab panel
4. 移动端 select
5. 必要时再改统计逻辑

容易漏改，而且错误往往表现为“标签点不动”或“移动端没有入口”。

建议：

1. 保留后端配置作为唯一事实来源。
2. Portal 前端启动后从 `/api/apps` 生成“注册表驱动的模块入口”。
3. 对 Portal 原生组件模块，例如 Dreamina、人像生成、历史、统计、密钥，用显式的 `component` 元数据描述，而不是散落在 HTML 和 `app.js` 中。
4. 每新增模块至少加一个前端自动化检查：桌面标签、移动下拉、panel ID、iframe src 是否一致。

### 2.5 前端文件已经很大，新人直接改有风险

当前规模：

| 文件 | 行数 | 现状 |
|---|---:|---|
| `portal/static/index.html` | 1106 | 页面结构、多个原生模块、内联样式混在一起 |
| `portal/static/app.js` | 2717 | Dreamina、人像、统计、密钥、历史、导演台逻辑全部在一个文件 |
| `portal/static/styles.css` | 1306 | Portal 壳、各业务模块、历史、统计、导演台样式混在一起 |

建议按“先低风险拆，再逐步组件化”：

1. 先把 `app.js` 拆成：

   ```text
   portal/static/js/
   ├── api.js
   ├── ui.js
   ├── portal-shell.js
   ├── apps/
   │   ├── dreamina.js
   │   ├── portrait.js
   │   ├── stats.js
   │   ├── keys.js
   │   ├── history.js
   │   └── director.js
   └── main.js
   ```

2. 继续保持无构建、ES Module 或普通 script 都可运行。
3. 把重复的上传、下载、轮询、toast、错误解释抽成共享函数。
4. `index.html` 只保留 Portal 壳和模块挂载点，模块模板逐步移到独立局部模板或 JS 渲染函数。

这种拆分不需要立刻引入 Vue/React 构建链，风险较小，但能显著降低新同学理解成本。

### 2.6 交互反馈仍大量使用浏览器原生弹窗

当前有多处 `alert`、`confirm`、`prompt`：

- Dreamina 账号重命名、删除、切换账号
- 密码重置
- 密钥删除
- 清理缓存
- 存档删除
- 上传失败

这类原生弹窗：

- 视觉上脱离 Portal 设计。
- 无法加帮助链接、状态码和后续动作。
- 无法统一埋点。
- 移动端体验不稳定。

建议：

1. 建一个 Portal 级轻量组件：

   ```text
   notify()
   confirmDialog()
   textInputDialog()
   taskErrorCard()
   ```

2. 错误提示统一包含：

   - 发生了什么
   - 可能原因
   - 下一步动作
   - 可以打开报错问答助手的入口

3. 危险操作统一使用红色确认对话框，而不是浏览器 `confirm`。

### 2.7 任务等待体验仍偏黑盒

当前任务状态有“排队中、处理中、查询中、已完成、失败”等，但没有：

- 当前排在队列第几位
- 预计还需多久
- 当前任务失败后最推荐的下一步

视频任务通常耗时较长，这会直接影响新人第一次体验。

建议先做轻量版本：

1. 显示当前模块进行中任务数量。
2. 显示自己的任务排队序号。
3. 对常见模型按平均耗时给“预计 X 到 Y 分钟”，明确标注是估算。
4. 任务完成后自动在结果区或全局历史里高亮新结果。
5. 网络轮询中断时，明确说“任务可能仍在后台运行”，并给出到历史记录查看的按钮，而不是只提示文字。

### 2.8 密钥库和子应用之间缺少直接衔接

当前“密钥库”只保存和复制：

- `portal/static/index.html:967-1039`

用户仍需手动去 Seedance 或图像生成模块粘贴。

建议：

1. 密钥条目增加“应用到 Seedance”和“应用到图像生成”按钮。
2. 点击后只填入当前浏览器会话中的表单值，不把密钥跨页面明文传递。
3. 子应用 API Key 为空时，显示一个“从密钥库选择”的快捷入口。
4. 在密钥条目上标明适合的供应商和模块，避免新用户复制错 Key。

### 2.9 提示词优化能力分散

当前：

- Seedance 有“✨ 优化”。
- 右侧导演台有优化、扩写、结构化、风格、负面词等能力。
- 图像生成模块没有同样的入口。
- 无限画布内部另有提示词 Skill 优化。

用户会困惑同一个能力出现在不同地方、行为不完全一致。

建议：

1. 将导演台的优化/扩写作为 Portal 级公共服务。
2. Seedance、图像生成模块、无限画布都调用同一套组件和同一组 Skill。
3. 每个入口显示“已由导演台处理”，避免用户以为结果来自不同模型。

### 2.10 “历史记录”已经很好，下一步应强化为“我的产出”

全局历史已经具备跨应用搜索、媒体预览、参数查看和下载：

- `portal/static/index.html:96-195`

可以继续增强：

1. 默认显示最近产物，而不是必须筛选。
2. 增加“只显示我的、我收藏的、上次下载过的”。
3. 图片和视频卡片增加“复用参数重新生成”。
4. 结果文件增加到期或已同步飞书状态。
5. 将每个子应用内部的“历史”入口和全局历史统一话术，避免用户不知道看哪个。

## 3. 推荐的第一版落地范围

如果只做一周，建议先完成以下五件事：

1. **帮助入口**

   - 顶栏加帮助按钮。
   - 首次登录显示 5 步新手检查清单。
   - 帮助抽屉链接到本手册。

2. **入口一致性**

   - 桌面标签和移动端下拉由同一份配置生成。
   - 修复移动端缺少“分镜布局”。

3. **顶部导航分组**

   - 创作 / 协作查询 / 个人管理。
   - 低频模块放入“更多”。

4. **全局 toast 和确认对话框**

   - 先替换最影响新人的删除、清理、上传失败等原生弹窗。

5. **任务反馈增强**

   - 提交成功后给出明确的任务编号。
   - 错误后给出到“历史记录”和“报错问答助手”的按钮。

做完这五件事，新实习生即使不看手册，也能在首屏找到正确路径。

## 4. 后续工程优化方向

### 4.1 组件化和模块拆分

建议长期目标：

```text
Portal Shell
├── 顶部栏 / 导航 / 身份
├── 应用注册表
├── 全局历史与产出库
├── 密钥库
├── 帮助与引导
└── 共享组件
    ├── 上传
    ├── 任务卡片
    ├── 错误解释
    ├── toast
    ├── 下载
    └── 确认对话框
```

首期不要追求 React/Vue 重构。先把共享函数和职责边界拆清楚。

### 4.2 自动化前端验收

建议增加：

- Portal 模块注册一致性测试。
- 关键表单提交的浏览器测试。
- 移动端下拉框和桌面标签一致性测试。
- 帮助按钮和手册链接存在性测试。
- 视觉回归截图。

已有测试可参考：

```text
ai-generation-portable-apps/tests/
```

### 4.3 前端埋点

至少记录：

- 用户第一次登录是否完成新手引导。
- 从哪个模块发起第一个任务。
- 任务提交前是否已有 Key。
- 错误发生后是否点击“报错问答助手”。
- 新用户是否在 24 小时内成功产出第一张图或第一个视频。

这能直接判断“新实习生的上手时间”是否真的下降。

## 5. 判断优化是否成功的标准

建议用以下验收条件，而不是只看“界面好不好看”：

1. 新用户首次登录后，能在 5 分钟内完成一张图或一个短视频。
2. 第一次任务失败时，页面能给出可执行下一步，而不是只显示英文错误。
3. 不需要问人，能自己找到密钥、历史记录、报错助手。
4. 移动端和桌面端看到的可用模块一致。
5. 新增一个子应用时，前端入口只维护一份配置，不再需要四处手改。
6. 重要结果在“历史记录”中都能找到并下载。
