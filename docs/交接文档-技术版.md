## 1. 这个平台是什么

### 1.1 一句话

**把公司内部的 AI 生成能力（文生图 / 图生图 / 文生视频 / 人像视频 / 本地免费推理）
聚合成一个局域网网页平台，同事用浏览器就能自助出片，并统一记账、审批与归档。**

### 1.2 它解决什么问题

- **不装环境**：同事只需要浏览器，不需要在自己电脑上装 Python、模型或 CLI。
- **统一入口**：图片、视频、人像、画布、分镜、飞书批量任务、报错问答、密钥、历史、统计全在一个站点。
- **管得住钱**：每一次生成都按任务登记用量与金额，能按人、按天、按模型核算（这是**核心红线**，见 4.4）。
- **批量生产**：飞书多维表格里的一行需求 → 自动规划提示词 → **人工审批** → 批量出片 → 回写飞书。

### 1.3 使用者在网页上看到什么

顶栏模块（**唯一事实来源是 `portal/apps.json` + `portal/static/js/portal-module-registry.js`**【代码】）：

| 入口 | 一句话用途 | 主要产物 | 归属 |
|---|---|---|---|
| Seedance | 文生视频 / 图生视频 / 首尾帧 / 视频延长与编辑 / 样片模式 | MP4 | 子应用 `seedance/` |

| Dreamina | 即梦账号的图片与视频（走本机 CLI） | 图片、视频 | 子应用 `dreamina/` |

## 2. 系统全貌

### 2.1 物理拓扑 **【实测】**

```
                    ┌──────────────────────────────────────────┐
   公司同事浏览器 ──▶│  服务器 A（本机，Windows 11 + RTX 4090 D） │
   （局域网，        │                                          │
     无需装环境）    │  · Portal 9090（HTTPS，唯一对外入口）      │
                    │  · 全部子应用（8787/8797/8888/8891/…/8903）│
                    │  · 飞书任务 Agent 8765                    │
                    │  · 模型机角色：AI Port 8801 + ComfyUI 8188 │
                    │    （模型文件在 E:\AI Tool\）              │
                    │  · Ollama 11434                           │
                    └───────────────┬──────────────────────────┘
                                    │ 每 10 分钟拉取用量
                                    ▼
                    ┌──────────────────────────────────────────┐
                    │  服务器 B（另一台同款部署，也在对外服务）   │
                    │  · 自己的 Portal + 子应用                  │
                    │  · 被 A 当作「远端来源」读取               │
                    └──────────────────────────────────────────┘
```

**两个关键认知，新人最容易搞错的**：

1. **服务器 A 同时就是"模型机"**。
   参考文档里《AI_Port_ComfyUI 本地部署手册》讲的「模型机」和《AI 工具工作流手册》讲的
   「网站服务器」**是同一台物理机**，不是两台。判定依据：
   - `config/local_ai.env.example` 里模型机地址写成 `http://<本机 hostname>.local:8801`
   - 本机 `E:\AI Tool\` 下同时有 `ComfyUI_windows_portable` 与 `projects\work\ai-portable-studio`
   - 本机 GPU = RTX 4090 D 24GB

2. **有两台服务器在同时服务（A 和 B）**，A 会聚合 B 的用量。见 2.3。

### 2.2 逻辑架构

```
                   ┌─────────────────────────────────────────┐
浏览器 ──HTTPS──▶  │  Portal (portal/app.py, stdlib HTTPServer)│
                   │                                          │
                   │  ① 静态页 + 登录/会话                     │
                   │  ② 子应用注册表 apps.json                 │
                   │  ③ 反向代理 /<app>/*  → 127.0.0.1:<port>  │
                   │  ④ 身份注入（X-Username / X-Is-Admin / HMAC）│
                   │  ⑤ 用量登记（X-Job-Id）+ 定价 + 账单       │
                   │  ⑥ 子应用编排与健康看护（每 15s）          │
                   └───────┬─────────────────────────────────┘
                           │ 子应用只监听 127.0.0.1（不能被局域网直连）
        ┌──────────────────┼──────────────────────────────────┐
        ▼                  ▼                                  ▼
  iframe 类子应用      Portal 原生组件类                  飞书 Agent
  seedance            dreamina（组件）                    8765
  nano-banana         volcengine-portrait（组件）           ↕ 也经 Portal 反代
  infinite-canvas     director（组件）
  previz / drama-pipeline / rag-assistant
        │
        ▼
  上游：火山方舟 / T8Star / Chiyun / 即梦 CLI / 本地 AI Port + ComfyUI
```

**要点**：子应用**不可能被局域网直连**（Portal 启动时强制 `HOST=127.0.0.1`【代码 `portal/app.py:1444`】），
所以所有流量、鉴权、记账都在 Portal 收口。这既是安全设计，也是「漏记账」风险集中出现的地方。

### 2.3 双机与「中心转发」 **【代码 + 实测】**

平台支持**多台同款部署互相汇总用量**，机制分两层：

| 机制 | 方向 | 代码 | 说明 |
|---|---|---|---|
| **远端来源拉取** | A **主动拉** B | `portal/remote_sources.py`、`portal/app.py:4756`、`:4766` | A 每 10 分钟去 B 的 Portal 拉最近 30 天用量记录 |
| **中心转发** | B 的统计查询**转发给 A** | `portal/app.py:4261 _forward_stats_to_center` | 当本机配置了 `center` 时，本机的「使用统计」查询直接转给中心，响应带 `X-Stats-From: center` |

配置文件：`portal/state/remote_sources.json`（**不进仓库，仅存在于本机**）。结构：

```jsonc
{
  "interval_minutes": 10,          // 拉取间隔
  "days": 30,                      // 拉取窗口
  "local_label": "服务器A",         // 本机在「来源」列显示的名字
  "sources": [                     // 要拉的远端（可以有多个）
    { "name": "服务器B", "base_url": "https://<B的局域网地址>:9090",
      "username": "admin", "password": "<明文口令>", "enabled": true }
  ],
  "center": { "base_url": "https://<中心的地址>:9090", "username": "…", "password": "…" }
}
```

**三条必须记住的运维口径**：

1. ⚠️ **不要双向拉取** —— A 已经拉了 B，B 上**不能**再配 `sources` 指向 A，否则两边互相把对方
   的用量再算一遍，统计直接翻倍。【来源：`_diag/DEPLOY_TO_SERVER_B.md`「千万别做的两件事」】
2. ⚠️ **`local_label` 必须显式配** —— 不配就用默认值，"来源"列会显示成错的机器名。
   本机（A）当前**没有配 `local_label`**，建议补上 `"local_label": "服务器A"`。
3. ⚠️ **`sources[].password` 是明文** —— 这是已知技术债，见 10.2。

### 2.5 技术栈与「零构建」原则

- **后端**：Python 3.12 + 标准库 `http.server` 为主；需要并发/第三方时才有 FastAPI + uvicorn 平行实现
  （见 3.3 的"双引擎"）。数据库用 SQLite（飞书 Agent、无限画布）。
- **前端**：**没有构建链**是硬原则。除 `infinite-canvas/` 用 Vite 构建并把产物提交进仓库外，
  其余全是「原生 JS + ES module + `<script>`」，直接改直接生效。
  引入 npm/npm 构建工具链会破坏「浏览器零依赖」这条基线。
- **为什么**：部署目标是"同事浏览器直接用"，服务器上不应该有前端构建步骤。

| local-ai | 8801 | 外部（模型机） | iframe `/local-ai/…` | 不在本仓库 | — |
| hello-world | 8899 | stdlib | **未接入** | 自带 `static/` | ✅（但没人调） |

#### ⚠️ 双引擎（新人第一坑）

**同一条业务逻辑有两套 HTTP 层**：`app.py`（stdlib）和 `app_fastapi.py`（FastAPI + uvicorn）。

- 由 Portal 用环境变量选：`<APP>_ENGINE=fastapi` 才走 uvicorn，**默认 `stdlib`**
  【代码 `portal/app.py:1470-1495`】。
- **本机实测：只有 `infinite-canvas` 和 `rag-assistant` 跑 FastAPI**，其余全跑 stdlib。
- 但 `seedance/`、`nano-banana/`、`dreamina/`、`volcengine-portrait/` 都**存在** `app_fastapi.py`，
  且 `Start All.bat` 会把它们都设成 fastapi —— 也就是说 **这四套 FastAPI 实现长期没在生产跑过**。
- **规则**：改 stdlib 侧行为时，**必须同步考虑 `app_fastapi.py`**，否则哪天有人用
  `Start All.bat` 起服务就会行为不一致（甚至 404）。
- ⚠️ **两个启动脚本对引擎的设置不一致**：`Start All.bat` 全开 fastapi；
  生产实际用的 `portal_watchdog.ps1` 只开无限画布和 rag。**别照着 bat 去推断生产行为。**

### 3.3 各子应用要点与易错点

> 详细版（含逐条行号依据）见随本文交付的调研笔记；这里给"接手必须知道"的部分。

#### Seedance（`seedance/`）—— 视频生成，最核心

- **定位**：多参考素材出视频（首尾帧 / 参考图 / 参考视频 / 参考音频），支持多并发、样片(草稿)模式、断点续跑。
- **入口**：`app.py`（stdlib，本机在跑）；端口 `8787`。
- **状态**：`JOBS` 字典在内存，**重启即丢**；但有落盘补偿 `state/jobs_backlog.json` + `recover_backlog()`。
- **上游**：火山方舟 Ark + 公司 TOS（对象存储）+ DeepSeek（提示词优化，实际走方舟端点）。
- ⚠️ **易错点**：
  1. 只改 `app.py` 忘了 `app_fastapi.py`（或反过来）；
  2. **素材引用口径**：`provider=volcengine` 时图片走 `data:` base64 URL（**不能**改走 `/files`），
     视频/音频**不能上传本地文件**，只接受公网 https 或 `asset://`；改上传逻辑极易触发
     `content[1].image_url.url is empty`；
  3. 参考图**补边**：Ark 只接受「高÷宽」在 0.39~2.50 区间，超范围会自动补边或拒绝 ——
     阈值改错会让用户"明明选好的图提交不了"；
  4. `seedance/state/deepseek.key` 里现在放的是 **`ark-` 开头的方舟 Key**，不是 DeepSeek 官方 key，
     别按文件名字面意思去改端点。

#### 图像生成 `nano-banana/`

- **定位**：文生图 / 图生图 / 扩图，四个 provider 可切：**本地 AI Port（默认，免费）**、T8Star、Chiyun、方舟 Seedream。
- **状态**：`JOBS` 内存态 + backlog 落盘；`state/secrets.json` 里是 `provider_keys`。
- ⚠️ **易错点**：
  1. **base_url「张冠李戴」**：历史上"选 Chiyun 但请求没带 base_url"会拿 Chiyun 的 key 去打 T8Star。
     现在代码强制"凡声明了 base_url 的云端 provider 一律锁自己的端点"——**别把这个改回
     `values.get("base_url") or DEFAULT_BASE_URL`**；
  2. 本地 provider 的 base_url 被**强制改写**，防止客户端把免费额度导去付费端点；
  3. `providers.json` 是"配置即注册表"：模型/尺寸能力写错前端下拉就错，
     而 `api_style` 决定走哪套协议（`openai_images` / `gemini_generate_content` /
     `ark_seedream` / `comfyui_workflow`）。

#### Dreamina（`dreamina/`）

- **定位**：通过**本机 `dreamina` CLI** 调即梦，支持多账号管理与额度显示。**没有 HTTP 上游**。
- **凭据** = CLI 登录态（`~/.dreamina_cli`），不是 API Key。
- ⚠️ **易错点**：
  1. **改错前端**：生产用户看到的是 `portal/static/app.js` 里的 `DreaminaApp` 组件，
     **不是** `dreamina/static/app.js`（那是直连 8888 的独立前端，正常没人访问）。
     改错位置的现象是"代码改了但用户没反应"；
  2. **双 admin 守卫**：后端 `X-Is-Admin` + 前端 `v-if="isAdmin"` 两层，新端点必须两层都过；
  3. CLI 信任链有 SHA-256 校验，`DREAMINA_CLI_TRUST_UPSTREAM=1` 是**紧急绕过开关，正常不要设**。

#### 人像生成（`volcengine-portrait/`）

- **定位**：火山方舟私域人像资产库（建素材组/素材、真人认证引用）+ 人像视频生成；另有本地 MiniMax H3 通道。
- **凭据**：`volcengine-portrait/config.json`（`api_key` / `access_key` / `secret_key` / `tos_bucket` / `tos_region`）。
- ⚠️ **易错点**：
  1. **`ProjectName` 默认 `COOP_YZQ`**（2026-09-11 由 `Seedance2.0` 改名而来 —— 项目 id 不同、
     素材库不共享），可用 `volcengine-portrait/config.json` 的 `project_name` 覆盖，
     但**请求体不能覆盖**（`handle_virtual_groups_post` 已移除该能力）。
     ⚠️ **AK/SK 是按 IAM 项目授权的**：换 AK/SK 必须**同时**把项目名换成该 key 被授权的那一个，
     否则素材库所有 Action 直接 `AccessDenied`（实测：新 key 只授权 `COOP_YZQ`，旧 key 只授权
     `Seedance2.0`）；
  2. **`CreateAsset` 需要公开可访问 URL**，Ark v3 上传后的 URL 需 Bearer，TOS 后端拉不到 →
     走免费图床兜底（`_upload_to_public_host`）。TOS 没配好会**静默**退到免费图床；
  3. **SK 不做 base64 解码**（与其他服务口径不同，别"统一"掉）；
  4. `config.json` 的保存是**整体回写** —— 任何"顺手清空字段"的改动都可能把公司凭据写坏；
  5. 该应用有 `app_fastapi.py`，且新端点必须**手工**在 fastapi 侧再声明一遍（`_LegacyBridge` 桥接），
     漏了在本机（stdlib）不会报错，**换引擎才爆**。

#### 无限画布（`infinite-canvas/`）

- **定位**：节点式画布；画布上的生成请求由本应用**翻译并转发**给 `nano-banana`(8797) / `seedance`(8787)。
- **必须 FastAPI**：`app.py` 是 18 行占位（直接 `sys.exit(1)`），但它**不能删**（Portal 靠它判断应用是否存在）。
- **数据**：`state/canvas.sqlite3`（SQLite + WAL，6 张表），**重启几乎不丢**。
- ⚠️ **易错点**：
  1. **改了前端必须重新 build 并提交 `static/`**：生产**不跑** `build.sh`，只服务已提交的构建产物。
     手工覆盖单个文件会白屏；`VITE_BASE` 必须是 `/infinite-canvas/`；
  2. `INFINITE_CANVAS_ENGINE=fastapi` 一旦丢失就 100% 起不来（会去跑那个 `sys.exit(1)` 的占位）；
  3. **统计路径极脆**：任务接口是 `/api/v1/jobs`，**不在** `/api/jobs` 前缀下，
     Portal 白名单里为它专门加了一条。改路由前缀必须同步改 Portal，否则**统计静默归零**；
  4. 三个名字会骗人的模块：`translate.py` 不是翻译服务（是**契约翻译层**，不调 LLM）；
     `ark_library.py` 不是模型库（是**方舟私域素材库适配器**）；
     `comfy_api.py`/`comfy_lib.py` **只能管理工作流、不能执行**。

#### 分镜布局（`previz/`）

- **定位**：浏览器 3D 素模摆位（14 关节木人 + 6 道具 + 景别相机），**不调任何模型、不产生费用**。
- 端口 `8896`；前端自带 `static/`（three r170 ES module + importmap，无构建链）。
- ⚠️ **易错点**：
  1. **用了 `import cgi`** —— Python 3.13 已移除该模块，**升级解释器会在导入期直接崩**。
     这是本应用唯一"未来必炸"的点；
  2. 「送画布」写死 Portal 前缀 `/infinite-canvas/...`：直连 8896 或改前缀，功能会**静默降级成 toast**；
  3. `_ID_RE` / `_FILE_RE` 是路径穿越与 zip-slip 的共同防线，放宽任一处会同时打开两个穿越漏洞。

#### 导演台（`director/`）

- **定位**：提示词优化/扩写（DeepSeek）+ 文生图（方舟 Seedream）。**目录里根本没有 `static/`**，

- ⚠️ **易错点**：Seedream 5.0 Pro 的尺寸映射是**实测约束、逐格写死**的（1K/1.5K/2K × 9 种比例），

#### AI 短剧全流程（`drama-pipeline/`）

- **定位**：8 阶段流水线（概念锚定→角色圣经→世界观→分场大纲→剧本→角色资产→表演设计→视频提示词）。

     所以新机上"没配也能跑"，很容易看错；

     排查本机出片失败**先看 8801**，别先怀疑短剧模块。

#### 报错问答助手（`rag-assistant/`）

- **定位**：粘报错文字/截图 → 先查飞书知识库 → 没命中就扫源码现场分析 → 有价值结论写回飞书待审核池。

## 4. 核心机制

> 这一章是"改了会出事"的部分。**动这四块之前，先把对应小节读完。**

### 4.1 Portal 的子应用编排 **【代码 `portal/app.py:1261-1600`】**

`AppManager` 负责拉起与看护所有子应用：

1. **`start_all()`**：遍历 `apps.json` 里的每个 spec，调用 `start_app()`。
2. **`start_app(name, config)`**（`portal/app.py:1428`）：
   - `managed: false` 的应用（`local-ai`）**只做探活，不拉起**；
   - 没有 `app.py` → 直接标 `missing`，不启动（`infinite-canvas/app.py`、`rag-assistant/app.py`
     这两个占位 stub 就是为满足这条而存在的）；
   - **`_kill_port_squatter(port)`**：先杀掉占用该端口的野进程（多副本抢端口的防线之一）；
   - 注入环境变量：`PORT`、`HOST=127.0.0.1`、`CORS=1`；若 spec 声明 `needs_tos_creds` /
     `needs_ark_key`，还会注入 `TOS_ACCESS_KEY`/`TOS_SECRET_KEY` / `VOLCENGINE_ARK_API_KEY`
     （**方舟 key 是从 seedance 的 `state/secrets.json` 里读出来再注入的**）；
   - 按 `<APP>_ENGINE` 决定跑 `python app.py` 还是 `uvicorn app_fastapi:app`（见 3.2）；
   - 子应用日志重定向到 `portal/state/logs/<name>.log`。
3. **`_health_loop()`**（`portal/app.py:1545`）：**每 15 秒**一轮：
   - 进程已退出 → 重启；
   - **HTTP 探针**（不是纯 TCP）：拿到任何 HTTP 响应（**含 404**）就算健康。
     这是为了抓"TCP 能连但 HTTP 永不响应"的应用层楔死（2026-09-02 人像事故的教训）；
   - 连续 **3 轮**不健康 → 杀掉并重启。

> ⚠️ **看门狗有内外两层，别改错**：
> - **外层** `portal_watchdog.ps1` **只负责 Portal 自己**（探 `/healthz`，连续 3 次失败才重启）；
> - **内层**就是上面这个 `_health_loop`，**由 Portal 负责所有子应用**。
> 往 `portal_watchdog.ps1` 里加子应用健康检查是**错的**。

### 4.2 Portal 的反向代理与身份注入 **【代码 `portal/app.py:5375`】**

`_proxy()` 是所有子应用流量的必经之路，值得完整理解：

1. **先记账**：`tracker.record(...)` 记一次请求；
2. **转发 Range 头**：`Range` / `If-Range` **必须转发**，否则 `<video>` 拖动进度会退化成
   每次重下整个 50~200MB 文件；
3. **凭据注入**：客户端带 `X-Key-Id` 时，Portal 从**服务端密钥库**取出真实 key 再注入
   （按 spec 的 `credential_scheme`：`api_key` → `X-Api-Key`；`ak_sk` → 拆成
   `X-Access-Key` + `X-Secret-Key`；`none` → 忽略）。**浏览器永远拿不到别人的 key**；
4. **身份注入**（子应用据此做按人隔离）：
   - `X-Username`（URL 编码，中文用户名安全）、`X-Portal-User-Id`；
   - `X-Is-Admin`：仅当 `role == admin`，**或**该 spec 声明了 `admin_permission` 且用户有该权限
     （Dreamina 的"懂运维的人可以管账号"就走这条）；
   - **HMAC 签名**：`(username, is_admin, ts)` 三元组会被签名，子应用**不允许**直接信任裸的
     `X-Is-Admin` 头；
   - `X-Forwarded-Proto` / `X-Forwarded-Host`：让子应用能拼出绝对 URL（回调、附件链接用）。
5. **流式转发**：用 `shutil.copyfileobj` 64KB 分块，**不缓冲整个响应体**
   （早期版本会 `read()` 完再转发，长任务会把代理线程堵死）；
6. **缓存控制**：对 `.html/.js/.css/.mjs` 强制 `Cache-Control: no-cache, no-store, must-revalidate`
   —— 这是"前端改完刷新就生效"的实现基础。

### 4.3 鉴权与角色 **【代码 `portal/app.py:1054 AuthManager`、`:3703`】**

- 存储：`portal/state/users.json`（密码哈希）+ `sessions.json`（会话）。
- 会话凭据有**两条通道**：
  - `session` **cookie**（浏览器导航用，`/`、`/login` 只能带 cookie）；
  - `X-Session` **请求头**（前端 fetch 用）。
  服务端**cookie 优先，其次 X-Session**。
- ⚠️ **历史大坑（已修，但要知道原理）**：登录页只用 `localStorage` 的 `X-Session` 判断"已登录"，
  而外壳 `portal-api.js` 只用 cookie → 切换 Portal 实例后两者判断相反 → **页面无限刷新**。
  现在的口径是：**登录页的"已登录？"探测必须只用 cookie**（因为 `/` 是浏览器导航，带不了 header）。
  改登录/会话相关代码前务必读 `portal/static/login.html` 与 `static/js/portal-api.js` 里的注释。
- **所有 API 未鉴权一律返回 JSON 401，绝不 302**（`portal/app.py:3703`）。原因：子应用路径
  如 `/seedance/api/media/upload` 不以 `/api/` 开头，早期实现会 302 到登录页，fetch 拿到 HTML，
  JSON 解析失败 → 表现为莫名其妙的"服务器拒绝了文件"。
- 角色：`user` / `admin` / `viewer`。权限判定走 `auth.has_permission(user, perm)`。
- `signup_enabled` 控制是否开放公开注册（管理员在「使用统计」页开关）。

### 4.4 用量统计口径 ★★★

> **`CLAUDE.md` 开篇连写四遍的那条红线就是这一节。任何改动都要先问：
> "这会不会影响统计？"**

#### 登记一次任务的三个必要条件 **【代码 `portal/app.py:3064-3086`、`:5375`】**

1. 请求是 **POST** 且路径命中白名单 `_is_job_request`：
   `/api/jobs`、`/api/text2image`、`/api/image2image`、`/api/text2video`、`/api/image2video`、
   `/api/frames2video`、`/api/multimodal2video`、`/api/multiframe2video`、
   `/api/virtual/jobs`、`/api/real/jobs`、**`/api/v1/jobs`**（最后这条是为无限画布专门加的）；
2. 响应状态 **200/201**；
3. 响应头里有**非空 `X-Job-Id`**。

**三条配套约定**：

- **取消接口刻意不发 `X-Job-Id`**（不计数）；**重试接口发**（按新任务重新计费一次）。
- **兜底登记**：能建任务但不上报 `X-Job-Id` 的应用（如飞书 run），走
  `_is_count_only_job_request` 的 `("/api/runs",)`，**只记次数与归属，token/金额留空**。
- ⚠️ **新加子应用若不发 `X-Job-Id`：功能全正常，统计永远是 0（静默失效）。**
  这是本项目最危险的"看起来没坏"的 bug 形态 —— 它已经真实发生过（无限画布的前缀不匹配）。

#### 从任务到钱 **【代码 `portal/app.py:1804 pricing_table`、`:1870 quote_generation`、`:2743 _job_poll_loop`】**

- Portal 轮询子应用的 `/api/jobs/<id>` 拿最终状态与产出**件数**；
- 视频时长从任务详情里读；token/金额通过方舟任务号去方舟拉 `usage` 再按单价算；
- 单价表在 Portal 内（`pricing_table()`），按 `model` 匹配 `price_family` 再乘分辨率/尺寸/有无输入视频；
- ⚠️ **`done` 必须是真实产出件数，严禁 `max(1, …)` 之类的兜底**（会让"0 产出"被记成 1 次计费）。

#### 账单与展示

- 数据落 `portal/state/usage.json`（按天、按用户、按应用）+ 每日 jsonl + `history.json`；
- 「使用统计」页支持按日期段查询、CSV / Excel 导出、按「日期 + 计费项」汇总（对齐方舟账单口径）；
- 「来源」列区分 服务器A / 服务器B / 本机（见 2.3）。

### 4.5 模型网关与 Provider 体系

- **`shared/model_gateway.py`**：统一各上游的端点、鉴权与协议差异。最典型的坑：
  方舟上的 DeepSeek v4 **必须显式下发 `thinking: {"type": "disabled"}`**，否则 max_tokens 全烧在
  `reasoning_content` 上、`content` 返回空串。声明了 `thinking_param: true` 的 provider 由网关自动处理。
- **`seedance/providers.json` / `nano-banana/providers.json`**：各应用的 provider 目录，
  定义 `base_url`、`models[]`、`defaults{}`、以及**决定协议的 `api_style`**
  （`openai_images` / `gemini_generate_content` / `ark_seedream` / `comfyui_workflow`）。
  前端 `bindProviderSwitch()` 按它重建模型下拉。
- **`shared/model_registry.json`**：跨应用共享的 provider 注册表（ark / deepseek / t8star /
  chiyun / local_gateway / local_llm）。
- ⚠️ **不支持只靠 JSON 新增"后端没实现过"的全新 API 协议** —— `api_style` 必须是程序已支持的类型。

#### ⚠️ 火山方舟：模型名 vs 推理接入点（`ep-`）——最容易整片 403 的地方

换到新项目 `COOP_YZQ` 后，**部分模型按模型名调用会直接 403 `AccessDenied`**（2026-09-14 实测：
`doubao-seedream-5-0-pro-260628`、`doubao-seedance-2-0-mini-260615`）；其余
`doubao-seedance-2-0-260128` / `-fast-260128` / `2-5-260628` 按名字仍可用。

这两个模型必须走控制台建的**推理接入点（ep-）**：

| 模型 | 接入点 |
|---|---|
| Seedream 5.0 Pro | `ep-20260912121809-6wt62` |
| Seedance 2.0 mini | `ep-20260912121738-vtd78` |

**接入点是"项目/部署相关"的**：换项目或换 key 时要在控制台重建，并同步更新全部落点 ——
`seedance/providers.json`、`seedance/static/app.js`、`portal/static/app.js`（`portraitModels`）、

（`_MODEL_MAX_DURATION`）。**漏一处就会出现"某个模块单独报 403"这种难查的现象。**

> `InvalidParameter` = 模型/接入点已路由成功（只是参数不合法）、`AccessDenied` = 没权限、
> `InvalidEndpointOrModel.NotFound` = 不存在。图像用 `size: "3K"`，视频用 `duration: 999`。
> 不要用"真跑一次"来验证，那是要花钱的。

### 4.6 飞书任务 Agent ★★（第二大子系统）

> 目录：`feishu-generation-agent/`，端口 8765，FastAPI。
> 这是全平台**业务逻辑最重**的部分：它把"飞书里的一行需求"变成"经过人工审批的批量生成任务"。

#### 核心原则

**"先看计划，再花钱"** —— **未审批不会提交任何生成任务**。

#### 两种入口

1. **直接分析需求文档**：粘贴飞书 docx / wiki 链接 → 读取文档与图片 → 规划任务。
2. **扫描多维表格任务**：刷新任务列表 → 只展示"需求来源是有效飞书链接且结果列为空"的记录 →
   手动选一条 → 开始分析。

#### 数据流（简化）

```
飞书文档 / 多维表格一行
   ↓ 读取（lark-oapi；文档正文 + 内嵌图片）
domain/document.py        文档解析
   ↓
integrations/planner.py   规划器（多模态模型）→ 任务计划 TaskPlan
   ↓                       含：提示词、比例/尺寸/时长/分辨率、参考素材分配、@图片N 标记
domain/plan.py            审批前可编辑（改提示词/比例/时长/参考图用途与顺序/勾选任务）
   ↓ 人工审批（3 个动作：退回重新规划 / 全部取消 / 批准所选任务）
graph/nodes.py + runtime  按任务调 seedance(8787) / nano-banana(8797) 提交生成
   ↓
产出回写飞书原记录（写回失败可"仅重试交付"，不会重复生成）
   ↓
feishu-output-sync        另有一条线：把服务器产出增量搬到「XX的AI产出」多维表格
```

#### 需要知道的关键机制（都是踩过坑的）

| 机制 | 说明 |
|---|---|
| **`@图片N` 标记契约** | 提示词里必须显式出现 `@图片N` 才算"用到了这张参考图"。**规划器漏写标记 → 下游把"漏标记"当成"没用上" → 自动把用户的参考图摘掉**（2026-10-13 真实事故）。修法是**自动补标记**，不是删素材 |
| **`blocking_issues` 是派生结论** | 它是"从别处算出来的"，不是原始数据。曾有"用户改对了时长却永远批不了"的 bug —— 因为改字段的接口**从不重算**这条。现在读视图 / patch / 审批前**三处都会重算**。**新增派生字段时，一定要在被依赖处重算或同步失效** |
| **绑定 vs 运行（竞态）** | 「领取/重跑」是**先写绑定、再建运行**。前端看到「处理中」会启动 5 秒盯守，盯守拉到"运行还没落库"就**把绑定判死并释放** → 用户可再领一次 → **重复计费**。现在有内存标记 + 10 分钟宽限期兜底 |
| **参考图去水印与台账** | 后台会给参考图做"去水印"。护栏曾两次误杀好结果（一次把用户手绘的红圈洗掉、一次把成功清洗判成"抹掉了内容"）。现行方向是**护栏降级为建议 + 用户看着选**：台账记 `decision`（auto/cleaned/original）+ `versions[]`，**预览与提交共用同一个"哪个版本生效"的判据** |
| **用户口径自动记忆** | 用户反复提的要求会自动沉淀到 `data/user_rules.json`，**说 3 次后才注入**后续规划。设计要点：判据要按"噪声"设计 —— 最贵的错不是漏记，而是把一次性指令当长期规则喂给下一个无关任务 |
| **运行状态与持久化** | 运行记录在 SQLite（`agent.sqlite3`），状态含 `created/planning/running/resuming/waiting_approval/waiting_review/delivering/…`。**重启会打断在跑的任务，且恢复是"重新入队重跑"而不是断点续传 → 可能重复计费**（这条是重启门禁存在的根本原因） |

#### 前端（`feishu-generation-agent/src/feishu_generation_agent/web/static/`）

- `app.js` 是**单文件单 IIFE（250KB+ / 5500+ 行）**，是整个应用的唯一主程序；
- 纯逻辑被刻意抽成 **6 个可 node 测试的小模块**：`review-state.js`（审批草稿状态机，最大）、
  `bitable-state.js`（多维表格任务状态机）、`reference-upload-state.js`、
  `reference-mutation-state.js`、`planner-prompt-state.js`、`prompt-diff.js`、`api-paths.js`；
- **性能收口（务必保留）**：
  - `ARTIFACT_HISTORY_RENDER_LIMIT = 6` —— 往次版本一次最多铺 6 个；当前成片与最新一版可直接播，
    **更老的才懒加载**（先放首帧预览图 + 点击播放）。起因：同一条记录最多 39 个版本，
    一屏几十路 `<video>` 并发取流会让 Chromium 弹「此页面没有响应」；
  - 运行详情轮询 **1 秒**（停在等人操作时降 **5 秒**）；任务记录盯守 **5 秒**（空闲时 15 秒）；
  - `AUDIT_PREVIEW_COUNT = 5`（审查员风险提示默认只铺 5 条）。
- ⚠️ **改这个应用的前端资源引用前先搜后端断言**：`web/app.py` 会把 `styles.css` **内联**进 HTML，
  并强制断言那句 `<link rel="stylesheet" href="static/styles.css">` **原样恰好出现一次**。
  给它加 `?v=` 会让**整页 500**。要 bump 的只有 `app.js?v=`。

#### 运维

- **重启必须走闲时门禁**：`_diag/restart_feishu_if_idle.py`（门禁与杀进程在同一进程内原子完成）。
  手动 kill 会打断同事任务并可能造成重复计费。
- 生产库：`feishu-generation-agent/data/` 下的 SQLite 与 json。

### 4.7 无限画布 / 自由创作 / 分镜布局

- **无限画布**：画布上的生成不自己调模型，而是**翻译成子应用的 JSON API** 再转发；
  任务接口 `/api/v1/jobs`（**统计白名单为它单独加过一条**）。数据在 SQLite，重启几乎不丢。
  前端是仓库里**唯一有构建链**的地方（Vite），**必须 build 后提交 `static/`**。
- **自由创作**：Portal 原生页面（`portal/static/free-creation/`），**不是独立子应用、不占端口**；
  它接入了本地 AI Port 的智能抠图 / 视频超分，所以依赖 8801。
- **分镜布局**：纯前端 3D 工具，**不调模型、不产生费用**；"送画布"通过 Portal 反代调无限画布的素材接口。

### 6.2 怎么新增一个模型 / Provider

1. 改 `shared/model_registry.json`（跨应用共享的 provider）或对应应用的 `providers.json`；
2. **`api_style` 必须是程序已支持的协议之一** —— 达不到就要写代码，不能只改 JSON；
3. 若 provider 需要特殊参数（如方舟的 `thinking`），在 `shared/model_gateway.py` 里声明
   `thinking_param: true`；
4. 重启对应子应用（改的是后端配置）。
5. ⚠️ 若模型会影响计费，**同步更新 Portal 的 `pricing_table()`**，否则账单金额不对。

### 6.3 怎么新增一个子应用（Checklist）

1. 建目录 `<new-app>/`，**至少要有 `app.py`**（Portal 靠它判断存在），端口从 `PORT` 环境变量读；
2. 在 `portal/apps.json` 里加一条（`name` / `display_name` / `port_env` / `port_default` /
   `mount` / `iframe_url` 或 `component_factory` / `job_type` 与 `job_type_rules` / `metrics`）；
3. **前端入口三处都要加**（这是既有技术债，见 10.2）：桌面 tab 按钮、tab panel（id 必须是
   `tab-<name>`）、移动端 `#mobileAppSelect` 选项；Portal 启动时会自检并 `console.warn` 缺哪个；
4. **发 `X-Job-Id`** —— 否则统计永远是 0。若新建任务的路径不在 Portal 白名单里，
   **必须同步在 `_is_job_request` 加路径**；
5. 端口不要落在别人的 100 端口窗口内（历史事故：seedance/nano-banana 曾共用 8787-8899 窗口）；
6. 发浏览器请求时注意：子应用**只能监听 127.0.0.1**，一切都要经 Portal 反代。
7. 参照 `hello-world/` 抄契约（HMAC 校验、`/api/config`、`/api/jobs`、finalize 回调）。

### 6.4 安全注意事项

- **仓库是 public**：不要把任何密钥、内网地址、飞书表格 ID、客户名写进**任何**被提交的文件。
  本机专属内容一律写 `CLAUDE.local.md`（已 gitignore）。
- **提交前务必 `git add <明确路径>`，永远不要 `git add .`** —— 工作区长期混着多个并发会话的
  在制品与备份文件（`.gitignore` 里有一整段"防 `git add .` 事故"的规则）。
- 已做的审计结论 **【实测 2026-11-09】**：
  - 对**所有已入库文件**做了密钥特征扫描（`sk-` / `cli_` / `AKLT` / `ark-` 等），
    命中的只有测试与示例里的**占位符**，**没有真实密钥入库**；
  - 真实密钥**都在 gitignore 覆盖的文件里**；
  - ⚠️ 发现一个**本地 stash** 里留有旧的 `.env.bak`（含真实值），**未被推送到公开远端**，
    建议清理（`git stash list` / `git stash drop`）以免日后误推。
- **待整改**：`remote_sources.json` 里的口令明文（见 10.2）。

## 7. 部署与运维

### 7.1 启动方式

| 场景 | 方式 |
|---|---|
| **生产（当前实际）** | `portal_watchdog.ps1` 常驻（计划任务 / 手动起），它拉起 `portal/app.py`；**子应用由 Portal 自己拉起** |
| 手动全量启动 | 双击 `Start All.bat`（Windows）/ `Start All.command`（macOS） |
| 测试环境 | `Start Test.command` / `Stop Test.command`（用另一套端口，不动生产） |
| 单跑某子应用 | `cd <app> && python app.py`（会用自己的默认端口） |

`Start All.bat` 的事实 **【代码】**：
- 窗口标题就是产品名 **RedCraft**；
- 要求 **Python 3.9~3.12**（**3.13 不行** —— 因为 `previz/app.py` 用了已被移除的 `import cgi`）；
- 启动前会 `call :load_local_ai_env` 读 `config/local_ai.env`；
- 会把 6 个应用设成 `*_ENGINE=fastapi` 后启动 Portal；
- 然后轮询 `https://127.0.0.1:9090/healthz`（失败则试 `http://127.0.0.1:9089/healthz`）等 Portal 就绪。

> ⚠️ `Start All.bat` **不会先杀旧进程**，会因端口占用静默失败、继续跑旧代码。
> 生产环境请用看门狗，不要重复双击。

### 7.2 看门狗（两层）

| 层 | 脚本 | 守谁 | 判据 |
|---|---|---|---|
| 外层 | `portal_watchdog.ps1` | **仅 Portal** | 探 `https://127.0.0.1:9090/healthz`（备选 http 9089），**每 10 秒**，**连续 3 次**失败才重启 |
| 内层 | `portal/app.py: _health_loop` | **所有子应用** | **每 15 秒**，HTTP 探针（404 也算活），连续 3 轮不健康才重启 |
| 模型机 | `local_ai_backends_watchdog.ps1` | ComfyUI(8188) + AI Port(8801) | 每 5 秒；看健康 URL + **队列是否非空** + **GPU 利用率/显存**（`nvidia-smi`）决定是否重启；有互斥体防双开 |

**要点**：
- 杀掉 Portal 后**约 30~40 秒**才会被拉起来（10 秒 × 3 次）；
- `portal_watchdog.ps1` 用互斥体（`Local\AI.Generation.Portal.Watchdog`）防止双看门狗；
- 它**只设 `INFINITE_CANVAS_ENGINE=fastapi`（及 rag）**，其余默认 stdlib；
- 停止方式：写 `portal/state/portal-watchdog.stop` 文件（脚本会读它并优雅停）；
- 模型机看门狗**必须有 GPU 感知**：ComfyUI 在负载下会"健康检查通过但实际卡住"，
  所以它会把"队列非空 / GPU 忙"当成"在工作，别重启"。

### 7.3 HTTPS 与证书 **【代码 `portal/app.py:967 ensure_certs`、`:1000`】**

- 自签证书在 `portal/state/` 下（`portal.pem` + `portal.key`），首次启动自动生成；
- **局域网 IP 每周会变（DHCP）**：`start_cert_ip_watcher` 会在 IP 变化时重生证书并重启，
  前端横幅提示新地址；
- **访问地址**：`https://<局域网IP>:9090`，首次需点「高级 → 继续前往」；
  `http://<局域网IP>:9089` 会自动跳。
- ⚠️ **不要用 `http://127.0.0.1:9090`** —— 9090 只讲 HTTPS，明文请求会被直接断开，
  浏览器显示"未发送任何数据"。这个坑极易踩。
- `curl` 测试**必须带 `-k`**（自签证书）；`Connection reset by peer` 常常不是 bug。

### 7.4 安全重启（闲时门禁）★★

> **同一个原则对两个服务都适用：重启会打断在跑的任务，而"恢复"是重新入队重跑、
> 不是断点续传 → 可能重复计费。**

| 服务 | 门禁脚本 |
|---|---|
| 飞书 Agent（8765） | `_diag/restart_feishu_if_idle.py`（**门禁与杀进程在同一进程内原子完成**，避免"刚判空闲就有新任务"的竞态） |
| Portal（9090，连带全部子应用） | `_diag/restart_portal_if_idle.py`、`_diag/restart_portal_when_idle.py` |

**门禁判据**：读各子应用 `state/activity_log.json` / `runs.json`，**非终态任务数为 0** 才算空闲。
终态集合大致为 `succeeded/failed/cancelled/interrupted/expired/done/finished/error/timed_out/partial_success`。

**正确姿势（务必照做）**：
1. 看到"空闲"要**连续两次**，且**最后一次任务提交距今 > 2 分钟**；
2. 然后再重启 —— 只看一次会踩到"刚判定空闲就有人提交"的坑（**在 A 机上已经打断过同事的任务两次**）。

**重启后的核对（三条都要过）**：
```powershell
# ① Portal 活着：应为 200 JSON {"ok":true,"service":"portal"}，而不是 302 到 /login
curl.exe -sk https://127.0.0.1:9090/healthz

# ② 端口都在（应约 10~12 个）
Get-NetTCPConnection -State Listen |
  Where-Object { $_.LocalPort -in 9090,9089,8765,8787,8797,8888,8891,8893,8895,8896,8900,8903,8801 } |
  Select-Object LocalPort, OwningProcess | Sort-Object LocalPort

# ③ 确认跑的是新代码：进程启动时间要晚于源码 mtime
(Get-Item portal\app.py).LastWriteTime
Get-Process -Id <PID> | Select-Object StartTime
```

### 7.5 服务器 B 的更新流程

参考 `_diag/DEPLOY_TO_SERVER_B.md`（**注意该文件的步骤已按当时的代码版本写，请对照现状**）。
标准顺序：

1. **备份**：记下 `git rev-parse --short HEAD`；拷 `portal/state/{history,users,download_files,remote_sources}.json`；
2. **确认没有任务在跑**（连续两次空闲 + 最后一次提交 > 2 分钟）；
3. **更新代码**（`state/`、`outputs/`、`archives/`、`logs/` 都在 gitignore 里，不会被覆盖）；
4. **写 B 自己的 `local_label`**（否则 B 会显示成错的机器名）；
5. **重启**（重启 Portal 会连带换掉全部子应用）；
6. **核对**：`healthz` 是 200 JSON、端口齐、统计页的「来源」列正确；
7. **回滚**：`git checkout <SHA>` + 还原 `.bak` + 重启。

**千万别做**：
- ❌ 有人在跑任务时重启；
- ❌ 让 B 也配 `sources` 去拉 A（**双向会重复计数**）。

### 7.6 多副本抢端口（历史事故，判据要会）

**症状**：网站打不开，或 `healthz` 行为异常。

**根因**：另一个工作目录里存在**旧副本的看门狗**，它把 9090 抢走了 —— 你更新了 A 目录的代码，
但对外服务的是 B 目录的旧进程。

**一眼识别的两条判据**：
1. `curl -sk https://127.0.0.1:9090/healthz` 返回 **302 → /login**（**正确实现是 200 JSON**）；
2. 该 Portal 进程**不写** `portal/state/portal.out.log`（日志时间戳停在被替换那一刻）。

**定位命令**：
```powershell
Get-CimInstance Win32_Process -Filter "ProcessId = <pid>" | Select-Object CommandLine,ParentProcessId
# 看父进程是谁 → 读那个进程对应的 portal_watchdog.ps1 里的 $PortalDir
```

**恢复**：先杀**错的看门狗**（否则 10~30 秒内又把错的拉起来）→ 杀错的 Portal 及其子进程 →
用**本仓库自己的** `portal_watchdog.ps1` 启动 → 确认 9+ 个子应用端口都回来了。

### 7.9 故障速查表

| 症状 | 先查什么 | 常见根因 |
|---|---|---|
| 网站打不开 | `curl -sk https://127.0.0.1:9090/healthz` | ① 用 https 了吗（9090 不讲 http）② 被别的副本抢了端口（7.6） |
| 页面无限刷新 | 浏览器 Network 看 `/` 与 `/login` 是否来回跳 | 登录页与外壳用了两套会话凭据（4.3） |

| **统计数字不对 / 永远是 0** | 该接口是否 POST、是否命中白名单、响应有没有 `X-Job-Id` | **最常见**：新应用/新路由没上报 `X-Job-Id`（4.4） |
| 重启后仍报旧 bug | 进程启动时间 vs 源码 mtime；端口 PID 是否早于 Portal 启动 | 在跑旧代码 / 孤儿子进程占端口 |
| 飞书「重跑必失败」「一直处理中」 | 绑定 `updated_at` 与对应 run `created_at` 谁早 | 绑定先落库被轮询判死（4.6） |
| 去水印"失效/去不掉" | 台账里那次是 `adopted` 还是 `kept`；清洗版与提交版是否同一张 | 护栏误拒 / 空操作被记账成成功（4.6） |
| 参考图"被自动排除" | 提示词里有没有 `@图片N` | 规划器漏写标记，下游把"漏标记"当"没用上"（4.6） |
| 图片提交被拒 | 参考图宽高比是否在 0.39~2.50 | Ark 的补边阈值（3.3 seedance） |
| 上传视频/音频报错 | 是否 `provider=volcengine` | 方舟不收本地视频/音频，只能公网 URL 或 `asset://`（3.3） |
| 本机出片失败（短剧/自由创作） | 8801 是否在听 | AI Port 没起来（看门狗或模型机侧） |
| 下载失败 | 是否用了页面内下载按钮 | 自签证书下 `<a download>` 会失败，已用 blob 方式绕过；复制链接另开标签页会失败 |
| `git push` 超时/连不上 | `git config --list --show-origin \| Select-String proxy` | `~/.gitconfig` 里有**失效代理**（URL 作用域键，`git config --get http.proxy` 看不到）。用 `git -c "http.https://github.com.proxy=" …` 绕过；大仓库推送要放宽 `http.timeout` |

## 8. 开发工作流

### 8.1 一条铁律：改动 → 验证闭环

本项目的正确工作方式是**先看改动的生效条件，再动手**。因为"代码改了"和"用户看到了"之间
隔着缓存、进程、构建产物三层：

| 改了什么 | 怎么生效 | 要不要重启 |
|---|---|---|
| Portal 静态前端（`portal/static/**`） | 刷新浏览器 | ❌ 不需要（Portal 强制 no-cache） |
| 子应用自带静态前端（`seedance/static/**` 等） | 刷新浏览器 | ❌ 不需要 |
| 飞书 Agent 前端（`web/static/**`） | 刷新浏览器 | ❌ 不需要（但**要 bump `app.js?v=`**） |
| 后端 Python（任何 `app.py` / `app_fastapi.py`） | **重启对应进程** | ✅ 需要 |
| 无限画布前端（`web/**` → `static/**`） | **必须 build 并提交 `static/`** | ❌ 但**必须 build** |
| 飞书 Agent 新端点 | 重启 8765（走闲时门禁） | ✅ 需要 |
| `shared-ui/` 下的 UI 令牌 | 回改 `shared-ui/` → 同步到各子应用 `ui/` | ❌ |

**两个高频翻车点**：
1. **改了后端没重启** → 报错行号和代码对不上，说明在跑旧代码（核对进程启动时间 vs 源码 mtime）。
2. **改了无限画布前端没 build** → 代码在 `web/`，生产服务的是 `static/`，表现为"改了没反应"。

### 8.2 改后端时的三条自检

1. **统计会不会受影响？**（`CLAUDE.md` 开头连写四遍的红线）
   —— 新增/修改创建任务的接口时，问：路径在白名单里吗？发 `X-Job-Id` 了吗？`done` 是真实件数吗？
2. **`app_fastapi.py` 要不要同步改？**（双引擎，见 3.2）
3. **重启要不要走门禁？**（涉及在跑任务时，见 7.4）

### 8.3 测试体系与怎么跑

| 层 | 位置 | 规模【实测】 | 跑法 |
|---|---|---|---|
| 仓库级后端 | `tests/test_*.py` | 87 个文件（含 `.mjs`） | `python tests/run_tests_local.py [路径]`（**本机没装 pytest 时的兜底 runner**，只支持 `tmp_path` / `monkeypatch` 两个 fixture）；装了 pytest 就直接 `pytest` |
| 仓库级前端 | `tests/test_*.mjs` | 30+ 个 | `node --test tests/test_xxx.mjs` |
| 飞书 Agent | `feishu-generation-agent/tests/` | **193 个文件**（unit / integration / frontend） | `cd feishu-generation-agent && uv run pytest -q`；前端 `.cjs` 用 node 跑 |
| Portal | `portal/tests/` | 含 `frontend/portal_rag_interceptor.test.cjs` | 同仓库级 |
| 分镜布局 | `previz/tests/` | unittest 24 例 + `test_core.mjs` + 真浏览器 smoke | `pytest previz/tests/test_app.py -q`；`node --test previz/tests/test_core.mjs` |

**合并操作手册（照抄即可，本次已验证）**：

> ⚠️ **前提认知：这个仓库目录就是生产运行目录。** Portal 每 15 秒做一次健康检查并会重启子应用，
> 所以**绝不要在活动的工作区里留下冲突标记**——万一某个子应用在那几秒被重启，它会加载到
> 带 `<<<<<<<` 的代码而崩溃。**合并必须在独立 worktree 里做**：

```powershell
# 0) 先囤一份安全备份（远端分支，不动 main）
git -c "http.https://github.com.proxy=" push teacherx main:refs/heads/main-handover-<日期>

# 1) 在独立 worktree 里合并 —— 生产目录完全不受影响
git worktree add -b merge-teacherx-<日期> ..\_merge_work HEAD
cd ..\_merge_work
git merge teacherx/main

# 2) 若有「整文件冲突」：先把三方（ours/base/theirs）都归一成 LF 再跑三方合并，
#    通常大部分会直接自动合并掉（本次 9 个冲突里 3 个如此）。
#    仍然剩下的才是真冲突，逐个按业务判断。

# 3) 在 worktree 里跑测试（本机没有 pytest 时用仓库自带 runner，
#    但它在 Windows 上清理临时目录有 bug，飞书那套建议用它自己的 venv：
#    feishu-generation-agent\.venv\Scripts\python.exe -m pytest tests -q）

# 4) 验证通过后回到生产目录，纯快进（瞬时、无冲突）
cd ..\ai-generation-portable-apps
git merge --ff-only merge-teacherx-<日期>

# 5) 推送
git -c "http.https://github.com.proxy=" -c http.timeout=600 push teacherx main

# 6) 清理
git worktree remove --force ..\_merge_work
```

⚠️ **快进会更新磁盘上的代码，但不会重启任何进程** —— 正在跑的服务仍然执行内存里的旧代码，
要生效必须重启（**走闲时门禁**，见 7.4）。

## 9. 历史事故档案与方法论

> 这个仓库最有价值的资产不是代码，是**踩过的坑**。下面按主题给索引；
> 每条都建议在动手前读一遍对应的 `CLAUDE.local.md` / 注释原文。

### 9.1 按主题索引

| 主题 | 事故 | 教训一句话 |
|---|---|---|
| **统计** | 无限画布路径不在白名单 → 用量静默归零；飞书行 token/金额恒缺；seedance 输入视频档位算错 | **"看起来没坏"的统计 bug 最贵**；新增任务接口必须核白名单 + `X-Job-Id` + 真实件数 |
| **参考素材** | 规划器漏写 `@图片N` → 用户的重要参考图被自动摘掉（两次）；去水印把用户手绘红圈洗掉 | **格式/噪音判据不许替用户删内容**；不合规优先"补齐"而不是"删除" |
| **去水印** | 护栏两次误杀成功清洗（一次是"最差单块"极值判据把水印去除本身判成改写）；确定性修补空操作被记账成"已去水印" | **极值统计当判据天生不稳**；**"成功"必须有独立度量来证**（退出码 0 不算）；护栏不确定时交给用户决定 |
| **审批** | 「审批任务无效」= 存量阻断项没人重算；改时长永远批不了 | **派生结论不要当数据存着不管** —— 要么被依赖时重算，要么改输入时同步失效 |
| **并发/竞态** | 绑定先落库、运行后创建 → 轮询把绑定判死 → **重复计费** | 「先落库再补建」的状态天生会被并发读误判；`release` 类操作要问"会不会顺手解锁别人的重试" |
| **前端性能** | 一屏几十路 `<video>` 并发取流 → Chromium「此页面没有响应」（同类事故**已发生三次**，每次都靠"上限 + 按 key 复用"收口） | 同类事故第三次出现时，**先找前两次的收口方式照抄** |
| **会话** | 登录页与外壳两套凭据 → 页面无限刷新 | 判断"是否已登录"的**唯一入口**要收口；浏览器导航只能带 cookie |
| **进程** | 别的目录的旧副本抢了 9090，服务的是旧代码 | 「重启后仍报旧 bug」先查**进程启动时间 vs 源码 mtime** |
| **鉴权** | 子应用路径不以 `/api/` 开头 → 302 到登录页 → 前端 JSON 解析失败，报"服务器拒绝文件" | 未鉴权一律 **JSON 401，绝不 302** |
| **上传** | 方舟不收本地视频/音频；参考图宽高比超范围被拒 | 上游硬约束要写进注释与校验，别靠用户试错 |
| **时间比较** | 重启门禁的 SQL 用字符串比较 ISO 与 `datetime('now')` → **当天永远判"忙"**，守候空转 2.8 小时 | **跨格式时间比较先归一**；"门禁一直拒绝"先验证判据是不是恒真 |
| **自动化记忆** | 把一次性任务指令当长期规则注入下一个无关任务 | **判据要按"噪声"设计** —— 自动记忆最贵的错不是漏记 |

### 9.2 可复用的排障方法论

1. **分清"接口慢"与"页面卡"**：出现「此页面没有响应」基本锁定**渲染主线程**（媒体元素数量、重绘频率），
   不要一头扎进后端。
2. **静态缺口 vs 时序问题**：模糊报告（"状态容易乱"）先拆成"可复现的静态缺口"（当场写测试钉死）
   和"只能抓现行的时序问题"（装只读探针）。
3. **改动前后都拿全量真实数据回放**，不要只跑合成测试。判别力自检：把修复关掉，测试必须变红。
4. **用户说"一直不好/失效了"时，先去看 `data/user_rules.json` / 返工要求** —— 那里常写着答案。
5. **静默 `except: continue` 排查成本最高**：状态卡在中间态时，日志里必须能查到原因。
6. **交付前用生产真实文件回放判据**，别用合成样本定阈值。

## 附录

### A. 术语表

| 术语 | 含义 |
|---|---|
| **Portal** | 平台统一入口（9090），负责鉴权、反代、统计、子应用编排 |
| **子应用（sub-app）** | 挂在 Portal 后面的独立服务，只能监听 127.0.0.1 |
| **规格 / spec** | `portal/apps.json` 里的一条子应用定义 |
| **托管（managed）** | 是否由 Portal 拉起并看护（`local-ai` 是 `false`） |
| **X-Job-Id** | 子应用在"创建任务"响应里回给 Portal 的任务号，**统计登记的唯一凭据** |
| **中心（center）** | 多机部署里负责汇总统计的那台；其它机器把统计查询转发给它 |
| **远端来源（source）** | 被本机拉取用量的另一台同款部署 |
| **样片模式（Draft）** | Seedance 2.5 的两段式：先出便宜 480P，满意再出 1080P 成片（各计一次费） |
| **档案 / 存档（archive）** | 用户保存的表单+参数+素材引用，可一键恢复（zip） |
| **台账** | 飞书 Agent 记录"参考图去水印用了哪个版本、谁选的"的持久化账本 |
| **门禁（idle gate）** | 重启前判断"现在有没有人在跑任务"的脚本 |
| **看门狗（watchdog）** | 常驻进程，负责把挂掉的服务拉起来 |
| **AK/SK** | 火山方舟的访问密钥与签名密钥（SigV4 用，不同于 Bearer API Key） |
| **asset://** | 方舟私域素材的引用协议（视频资产必须用它） |
| **TOS** | 火山对象存储（产物/素材的中转） |
| **vault / 密钥库** | Portal 里的个人密钥存储（只保存与复制，需手动粘到子应用） |
