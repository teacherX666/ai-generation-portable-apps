## 三、网络稳定性（IP 每周变化）✅

### 硬编码 IP 盘点：运行时代码零硬编码，只有文档过期

- 当前实际 IP 已是 **192.168.30.36**（DHCP 已从 .5 变过一次），文档全部过期
- 运行时代码全部动态取 IP：`portal/app.py:180-218` `get_lan_ip()`（ifconfig 扫描→私网过滤→UDP 回源兜底）；CORS 白名单（94-131）、`_platform_status`（1634）、证书（235）、启动横幅（2245）均动态；`apps.json` iframe_url 全相对路径；`启动器.command` 用 `${ip}` 变量
- 文档类过期位置（低危，仅误导排障）：CLAUDE.md、AGENTS.md、docs/deployment.md、docs/pending-fixes.md、docs/2026-06-25-fix-plan.md、docs/security-hardening-v2-plan.md、deploy/deploy.sh、deploy/rollback.sh

### 证书逻辑（`portal/app.py:231-272` `ensure_certs`）—— 高严重度

- 证书实际在 **`portal/certs/`**（不是 CLAUDE.md 说的 `portal/state/portal.pem`，该描述已过期）
- **只在进程启动时调用一次**。运行中 DHCP 换 IP 不触发重生 → 新 IP 不在 SAN → 同事访问新 IP 看到证书错误且**无法绕过**（「继续」只救「自签未信任」，救不了「SAN 不匹配」）→ 必须有人重启 Portal 才恢复；重启后新密钥新指纹 → **全员再次手动「高级→继续」**
- 失败链路：IP 变化（运行中）→ 全员断连 → 手动重启 → 全员重新信任。**每次 IP 变化 = 全员中断 + 全员重新信任**
- 附带缺陷：`_ALLOWED_ORIGINS` 注释称「每次调用刷新」，实测惰性初始化一次——IP 变化后 CORS 白名单冻结在旧 IP，直连子应用端口时 preflight 被拒（高）

### URL 传播链（外发到同事/飞书的链接）

| 链路 | 位置 | 失效后果 | 严重度 |
|---|---|---|---|
| 每日日报飞书卡片 `open_url` → `https://{ip}:9090/api/reports/daily/...` | `portal/daily_report.py:379-411` + `portal/state/feishu.json` 的 `portal_base_url`（当前为空） | 历史卡片按钮全部打不开；目前 `enabled:false` 潜伏，启用即暴露 | 中 |
| 飞书 Agent 素材库 `storage_url` 默认 `http://127.0.0.1:8765` | `feishu_generation_agent/.../storage/asset_library.py:127` | 对同事指向他们自己机器，本身即坏（与 IP 变化同族） | 中 |
| 飞书审批/结果消息、feishu-output-sync 表格 | `feishu_delivery.py` 等 | 全是飞书托管链接，无 LAN IP | 无 |
| iframe 注册、download_files.json、存档 zip | portal/apps.json 等 | 相对路径/本地映射 | 无 |

### 本机网络现状（实测）

- 主机名：`Mac mini` / `Mac-mini-3` → mDNS 名 **`Mac-mini-3.local`**，本机解析正常返回 192.168.30.36；**Windows 同事的 .local 解析需实测**
- en0（Ethernet，MAC `1c:f6:4c:65:43:c5`）192.168.30.36/24；无 Wi-Fi；VPN 接口 240.0.0.1 已被 get_lan_ip 黑名单过滤
- 9089→9090 跳转（`portal/app.py:2267-2282`）取请求 Host 头拼接，**天然免疫 IP 变化**，无问题

### 公网方案关系

`docs/公网部署/01-迁移方案.md` + `deploy/`：迁火山云服务器 + `https://easyq.cn`（Caddy 终结 TLS + Let's Encrypt）是本案**终极解法**（本机退役后全部问题消失），当前卡在备案/切换决策门。

### 可选技术方向（待拍板）

1. **mDNS .local**（Mac-mini-3.local）— 零配置，但 Windows 解析不可靠、证书 SAN 需加 DNS 条目，要先实测同事机器
2. **静态 IP** — 系统设置手动指定，5 分钟搞定，但可能撞 DHCP 池、需网管配合
3. **路由器 DHCP 保留** — en0 MAC 绑定固定 IP，一劳永逸无冲突，需路由器管理权限
4. **局域网 DNS** — 内网 A 记录指向服务机，需公司 IT 配合，证书 SAN 需含主机名
5. **隧道 + 域名**（Cloudflare Tunnel）— 本机零改动，但流量绕公网、依赖外网
6. **直接上公网域名（easyq.cn 迁移）** — 一次到位，代价：备案状态 + 一次完整搬迁
