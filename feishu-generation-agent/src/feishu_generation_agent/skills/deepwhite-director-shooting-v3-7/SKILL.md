# Deepwhite导演拍摄技能v3.7

作者：DeepWhite

把锁定剧本转译为可执行的摄影、构图、调度、表演、声音、故事板和 Seedance 2.5 提示词。只设计视听表达，不擅自改编剧情。完整保留 v3.6 的 Gate、状态机和最终提示词格式；仅强化文戏的镜头任务、内部运动、切镜判断和动势连续性。

## 不可违反的约束

- 把用户最新确认的剧本作为唯一剧情源。逐字保留台词的说话人、文字、顺序和含义。
- 只补充摄影、构图、调度、表演微节拍、环境活动、声音和生成控制；不得改变剧情事实、人物动机、关系、因果、胜负、伤势或结局。
- 遇到时长、容量、提示词长度或生成稳定性冲突时，拆分工作段或请求改编授权；不得自行删改剧本。
- 把用户当前或此前消息中的明确选择视为已通过对应 Gate，记录后继续，不重复询问。
- 未满足当前分支的硬性 Gate 时停止，不提前生成故事板、正式视频提示词或最终交付。

## 状态机

按顺序维护以下状态，并在关键回复中简短记录已确认项：

| 状态 | 完成条件 |
|---|---|
| `SOURCE_READY` | 已取得明确剧本正文、制作范围和目标平台；缺少剧本时只索取必要内容 |
| `SCRIPT_LOCKED` | 已建立 `EV/DLG/LOCK` 清单和剧本版本 |
| `ASSET_CONFIRMED` | 已确认使用或不使用资产；使用时资产映射也已确认 |
| `MODE_CONFIRMED` | 已确认使用或不使用故事板 |
| `SPATIAL_CONFIRMED` | 已确认俯视调度，或已记录无需调度图的理由 |
| `PLAN_CONFIRMED` | 已确认时长判断、工作段、拍摄形式、文字分镜、排版和覆盖表 |
| `STORYBOARD_CONFIRMED` | 仅故事板分支；返图已审查、必要返修、复审并获用户确认 |
| `PROMPTS_VALIDATED` | 提示词已完成内容自检和机械校验 |
| `DELIVERED` | 已按用户要求保存并交付最终文件 |

不要用状态名代替自然语言沟通；状态用于防止漏步、越步和重复提问。

## Gate协议

- 只在缺少的决定会实质改变后续结果时暂停。
- 一次只提出当前最早的必要确认；用户已明确回答的项直接记为已确认。
- 资产策略是取得剧本后的第一个确认节点；故事板方式在资产策略之后确认。故事板方式按 `SEG-xx` 工作段记录，不把第一段的选择自动套用到后续段。
- 把“直接写视频提示词”“不要故事板”视为不使用故事板；把“先出宫格分镜”“生成故事板”视为使用故事板。
- 需要资产但映射不清、需要空间确认但方位不清、目标时长不足且无改编授权时，停止并请求最小必要信息。

## 执行流程

### 1. 锁定剧本

1. 完整读取用户指定范围，区分剧本事实与导演可设计层。
2. 读取 `reference/SCRIPT_FIDELITY.md`。
3. 建立 `EV-xx`、`DLG-xx`、`LOCK-xx` 清单；把每句台词原文写入清单。
4. 记录剧本版本和用户已授权的修改范围。后续产物都回指这些编号。
5. 同时维护 `script_manifest.json`，供最终机械校验使用；格式见校验脚本的 `--help`。

### 2. 确认资产策略

1. 读取 `reference/ASSET_CONFIRMATION.md`，判断人物、场景、道具、动作姿势和风格资产的价值。
2. 用户尚未选择时，先给出判断和理由，再询问使用或不使用；等待回答。
3. 用户选择使用时，完成资产清单、上传顺序、参考边界和用途映射，并等待确认。
4. 用户选择不使用时，记录真实的一致性风险；后续完全省略素材句柄和空占位。

### 3. 确认故事板与空间

1. 用户尚未明确故事板方式时，询问使用或不使用并等待回答。
2. 对当前工作段分别记录 `SEG-xx：使用故事板 / 不使用故事板`；前一工作段的选择不自动继承到后一工作段。
3. 判断当前工作段的多人关系、关键道具落点、遮挡、视线、运动轴线或摄影机方位是否会影响结果。
4. 条件成立时读取 `reference/SPATIAL_BLOCKING.md`，输出俯视调度并等待确认；否则记录跳过理由。

### 4. 规划时长、工作段与文字分镜

1. 读取 `reference/SEEDANCE_2_5_RULES.md` 获取当前模型限制，再读取 `reference/PLANNING_CAPACITY.md`。
2. 比较用户目标时长与忠实呈现估算。目标不足时报告差额，等待用户延长时长或明确授权改编。
3. 按剧情目标、动作结果、情绪转折、模型容量和故事板容量拆分 `SEG-xx`。
4. 为每个工作段选择 `单镜头一镜到底` 或 `多镜头剪辑`；一镜到底的文字节点表示连续路径，不表示切镜。
5. 文戏或混合戏中的文戏区间读取 `reference/DRAMA_SHOT_MOMENTUM.md`：为每个镜头确定主视觉任务、连续动作链、摄影机四段式、切镜必要性、第一帧、结束帧和下一镜动势继承；这些判断写入文字分镜，不改变正式提示词字段。
6. 确定实际画面节点数、故事板排版和阅读顺序，不为凑整增加空格、重复画面或剧情；没有新信息、节拍或空间任务的相邻文戏节点优先合并。
7. 输出时长判断、工作段表、文字分镜、`EV/DLG/LOCK` 覆盖表和跨段连续性账本，等待用户确认。

### 5A. 不使用故事板

对标记为“不使用故事板”的当前 `SEG-xx`，在该段的 `PLAN_CONFIRMED` 后直接进入视频提示词。完全省略该段故事板字段、故事板占位和相关素材句柄；不能因其他工作段使用故事板而补写本段故事板。

### 5B. 使用故事板

1. 对标记为“使用故事板”的当前 `SEG-xx` 读取 `reference/STORYBOARD_ASSETS.md`。
2. 按当前工作段生成一张完整宫格图；生成前确认该段格数、排版和阅读顺序。
3. 由 Codex 生成时使用 `$imagegen`；用户在其他平台生成时交付完整提示词并等待该段整张返图。
4. 实际打开该段返图，逐格审查结构、剧本覆盖、人物道具、空间轴线、动作连续性、简笔画火柴人风格、文字污染和肢体错误。
5. 硬性项失败时编辑当前完整原图，锁定其他格；修改后重新打开并复审。
6. 内部审查通过后仍等待用户确认。只有当前 `SEG-xx` 的 `STORYBOARD_CONFIRMED` 后，才进入该段视频提示词；不能用其他段的故事板确认代替。

### 6. 编写视频提示词

1. 读取 `reference/PROMPT_PATTERNS.md`，按当前拍摄形式选择模板。
2. 风格需要提炼、参考图存在风格边界或用户要求特定质感时，读取 `reference/STYLE_BLOCK.md`。
3. 剧本只有泛情绪、需要可表演微反应时，读取 `reference/MICRO_BEATS.md`，只选择当前情绪弧线需要的少数节拍。
4. 摄影机运动需随情绪变化，或焦段、手持、推进和冻结对结果关键时，读取 `reference/CAMERA_EMOTION.md`。
5. 先判断当前工作段是文戏、战斗/高运动戏或混合戏。只有这一步允许读取并使用动态模块：
   - 文戏：读取 `reference/DRAMA_SHOT_MOMENTUM.md`，先完成镜头主任务、主体动作链、摄影机四段式、切镜理由、第一帧/结束帧和动势继承判断，再严格压入 `PROMPT_PATTERNS.md` 的原有字段；不得增加或更换最终字段。
   - 战斗/高运动戏：读取 `reference/MOTION_MODE_ROUTER.md`、`reference/DYNAMIC_MOTION_PHYSICS.md`、`reference/DYNAMIC_PLANNING.md` 和 `reference/DYNAMIC_PROMPT_CONTRACT.md`，在原有提示词结构中替换具体动作字段；不改变前面任何 Gate、分镜、故事板或空间步骤。
   - 混合戏：只在提示词的动态时间区间使用动态字段，其他区间按 `DRAMA_SHOT_MOMENTUM.md` 完成导演判断后仍使用原文戏字段；两类区间共享人物、道具、轴线、环境与动势连续性。
6. 写入素材边界、一句话概述、连续时间戳、画面构图、机位、动作与表演、逐字对白、声音、连续性和结束状态。文戏多镜头的 `机位` 必须体现可执行的起点、跟随对象、触发变化和结束动势；`转场` 必须按需继承位置、速度、方向、重心、视线、道具手位、摄影机侧位、环境运动和声音桥。
7. 使用故事板时只引用已确认返图的构图、站位、动作方向和摄影路径；不继承格框、文字和简笔画火柴人画风。

### 7. 校验并交付

1. 先完成导演判断与视觉连续性自检，再运行：

```text
python scripts/validate_delivery.py <Shotlist.md> --manifest <script_manifest.json>
```

2. 修复所有 `ERROR` 后重新运行；人工判断并处理 `WARNING`。校验脚本不能替代返图审查和剧情语义判断。
3. 默认读取 `reference/DELIVERY_FORMAT.md` 并保存完整 Markdown。
4. 用户明确要求 HTML 时，再读取 `reference/HTML_QA.md`、`reference/PLAN_TYPES.md` 和 `templates/HTML_TEMPLATE.md`，生成后进行真实浏览器或截图检查。
5. 用户明确要求 DOCX 时使用文档技能；不要主动询问是否更换格式。

## 返工路由

| 用户变更 | 返回状态 |
|---|---|
| 修改剧本、台词、人物关系或结局 | `SCRIPT_LOCKED`，重建受影响的 `EV/DLG/LOCK` |
| 新增、替换资产或改变参考用途 | `ASSET_CONFIRMED` |
| 改变某个 `SEG-xx` 是否使用故事板 | `MODE_CONFIRMED`，只重跑该段的故事板分支或非故事板分支 |
| 改变人物、道具、摄影机位置或运动轴 | `SPATIAL_CONFIRMED` |
| 改变总时长、剧情范围、拍摄形式、节奏或格数 | `PLAN_CONFIRMED` |
| 修改故事板画面 | `STORYBOARD_CONFIRMED`，编辑完整原图并复审 |
| 只修改提示词控制措辞 | `PROMPTS_VALIDATED`，保留锁定剧本并重新校验 |
| 只改变交付格式 | 保留内容状态，只重做格式与版面检查 |

只重做受影响范围；未受影响且已确认的内容保持不变。若用户在第一段完成后要求第二段切换故事板模式，保留第一段交付，第二段从 `MODE_CONFIRMED` 重新进入当前段的 5A/5B 分支；不得回退整个项目，也不得沿用第一段的模式。
