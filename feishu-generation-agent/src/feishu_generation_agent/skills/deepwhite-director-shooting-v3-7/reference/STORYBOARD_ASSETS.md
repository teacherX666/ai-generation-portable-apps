# 黑白简笔画火柴人多宫格故事板工作流

故事板分支只在用户明确为当前 `SEG-xx` 选择“使用故事板”后执行。每个工作段一次生成一张完整的多行多列宫格图；实际格数 `N` 由剧情与拍摄需要决定，通常为 2—16 格，16 格只是上限。必须经过实际返图审查、必要修改、复审和用户确认。不同工作段可以分别选择使用或不使用故事板，前一段的模式不自动继承。

## 目录

1. 前置状态
2. 格数、排版与简笔画规范
3. 故事板生成提示词
4. 生成方式
5. 返图审查
6. 自动修改与复审
7. 用户修改
8. 交付与确认
9. 写入视频提示词

## 1. 前置状态

生成故事板前必须满足：

```text
已选择故事板方式：使用故事板
已确认资产策略：使用 / 不使用
已确认资产映射：是 / 不适用
已确认位置：是 / 本次无需位置图，原因：...
已确认文字分镜与时长：是
已确认故事板格数：N格（2≤N≤16）
已确认故事板排版：规则矩阵 {ROWS}行×{COLS}列 / 多行异列 {ROW_COUNTS，例如3+2}
已确认阅读顺序：默认从左到右、从上到下 / 其他明确顺序
已锁定剧本：是；本工作段EV/DLG覆盖：完整
```

文字分镜、实际格数或排版未确认时，不生成故事板，也不写视频提示词。

## 2. 格数、排版与简笔画规范

### 格数与排版

- 每个工作段将已确认的 `N` 格放入同一张完整图片，不逐格分别生成。
- `N` 由有效镜头或路径节点数决定，通常为 2—16；不得默认或强迫使用16格。
- 每格对应已确认文字分镜中的一个有效镜头、剪辑节拍或路径节点，不添加装饰性空格、重复面板或凑数节点。
- 宫格图支持多行、多列排列。生成前确认总格数、总行数、每行列数、画格比例和阅读顺序；返图必须与这些确认一致。
- 优先使用规则矩阵，满足 `N=ROWS×COLS`；例如2×2、2×3、2×4、3×3、2×5、3×4、4×4。
- `N` 不适合规则矩阵时，使用多行异列排布并写成每行格数之和，例如3格为 `1+2`、5格为 `3+2`、7格为 `4+3`、11格为 `4+4+3`。
- 只有 `N=2` 时，多行多列无法同时成立；不得为排版凑格，可在用户确认后例外使用1×2或2×1，并记录例外原因。
- 多行异列允许经确认的宽面板或跨列面板以填满版面，但不得把两个独立镜头擅自合并为一格，也不得产生装饰性空位。
- 默认按从左到右、从上到下阅读；多行异列必须明确每格所在行列、相对宽度和阅读顺序。
- 多镜头：一格表示一个镜头或剪辑节拍。
- 一镜到底：一格表示同一连续摄影机路径中的构图节点，不代表切镜。

排版必须由实际 `N` 和画面可读性决定，不得机械套用。格数不足16时，直接使用实际需要的格数；若为获得清晰排版而细分节点，只能细化原剧本已有动作，不能新增剧情、台词、结果或重复画面。

### 默认简笔画火柴人风格

没有用户明确覆盖时，固定使用白底黑线简笔画火柴人故事板：

- 白色或暖白色纯净背景，以细黑线和少量浅灰表达画面；
- 人物主体使用圆形头部、单线躯干和单线四肢的火柴人结构，不绘制写实人体体积、肌肉和复杂服装褶皱；
- 按角色需要，只用少量发型轮廓、眉眼、嘴形、手势、披风或标志性饰件区分身份、朝向和情绪；
- 远景人物保持最简火柴人；近景人物可以增加简化头发、眉眼和手部轮廓，但仍必须明显是简笔画火柴人；
- 场景地形、建筑、法阵、兵器和关键道具可以比人物更具体，以清楚表达空间、比例、攻击方向和接触点，但保持轻线稿和低细节；
- 速度、风、冲击、法术和运动轨迹使用少量清楚的线条表达，不用浓重特效或大面积阴影；
- 人物动作轮廓、朝向、发力方向、接触点和结果必须一眼可读；
- 不使用彩色、棕褐色、金色点缀、写实照片、写实渲染、3D成片、动漫精细人物、油画、重黑漫画块面或大面积脏灰；
- 不生成台词框、字幕、数字、格号、拟声词、箭头说明、标志或水印。

若用户明确要求其他故事板风格，先说明这会覆盖“黑白简笔画火柴人”默认，再按用户要求执行。


## 4. 生成方式

写好故事板提示词后询问：

```text
请选择故事板生成方式：
1. 由 Codex 一次生成当前工作段的整张{N}格、多行多列黑白简笔画火柴人故事板；
2. 你使用这条提示词在其他平台生成，再上传同一张完整返图。
```

### Codex 生成

1. 读取 `$imagegen` 技能。
2. 一次调用只生成当前工作段的一张完整 `N` 格多行多列宫格图。
3. 图像生成后结束当前回复；在下一轮读取实际返图，不在生成图片的同一回复中继续分析。

### 用户自行生成

交付一条完整可复制提示词，等待用户上传整张返图。不要要求逐格上传。

## 5. 返图审查

收到返图后必须实际打开或查看图片，按已确认阅读顺序逐格检查。审查通过不等于用户确认。

### 硬性通过项

任一失败即不得交付为可确认版本：

- 总格数正好为已确认的 `N`；总行数、每行列数、已确认的宽面板/跨列面板、画格比例和阅读顺序符合方案；无缺格、多格、未经确认的合并格或装饰性空格。
- 除已记录并经用户确认的 `N=2` 例外外，宫格图必须形成多行、多列排列，不得退化成单行长条或单列长条。
- 画面为白底黑线简笔画，人物明确采用圆头、单线躯干和单线四肢的火柴人结构；无彩色污染、写实人体、精细动漫人物、写实渲染、3D成片感或重黑漫画块面。
- 每格可见人物、景别、机位、构图、动作和结束姿势符合已确认文字分镜。
- `N` 格完整覆盖本工作段全部 `EV/DLG` 归属；没有因画面容量删除、改序、新增或重复剧情，台词对应的说话人与反应对象正确。
- 人物通过简化发型、眉眼、服装轮廓或标志性饰件保持可识别；道具和场景关键地标跨格一致。
- 多人左右关系、180度轴线、移动方向、遮挡和空间层级没有无理由颠倒。
- 前一格结束状态能够连接后一格开始状态；一镜到底节点不能呈现为互不相干的切镜。
- 无额外人物、重复人物、人物融合、严重肢体畸形、穿模或无法识别的接触点。
- 无字幕、台词框、数字、格号、拟声词、箭头说明、标志和水印。

### 质量审查项

- 相邻面板的景别、机位、人物显隐或信息有明确变化，不是重复构图。
- 动作剪影、发力方向、接触点和结果可读。
- 空间、道具或环境变化形成连续因果，并在后续格保持。
- 线条轻盈干净，浅灰只用于必要层次，关键主体不被脏灰或速度线遮挡。
- 画格边缘留有安全空间，头部、武器、手部和关键接触点不过度裁切。
- 最后一格有明确结束状态、结果或悬念。

### 审查输出表

```markdown

- 已确认格数：{N}
- 已确认排版：{LAYOUT_SPEC，例如2×3 / 两行3+2}
- 已确认阅读顺序：{READING_ORDER}

| 面板 | 对应文字分镜 | 实际画面 | 硬性项 | 质量项 | 问题与处理 |
|---|---|---|---|---|---|
| SB-01 | 镜头1 / 路径节点1 | ... | 通过/失败 | 通过/需优化 | ... |
| ... | ... | ... | ... | ... | ... |
| SB-{N} | 镜头N / 路径节点N | ... | 通过/失败 | 通过/需优化 | ... |

整图结构与实际格数：...
剧本EV/DLG覆盖：...
简笔画火柴人风格：...
人物与道具一致性：...
空间轴线与动作连续性：...
文字、水印与畸形：...
审查结论：通过 / 需要修改
```

不要相信返图中自动生成的格号或文字；面板编号由确认后的视觉阅读顺序确定。

## 6. 自动修改与复审

硬性项失败时，先修改再向用户提交可确认版本。

1. 保存并锁定返修前的当前完整多宫格原图。
2. 明确目标格号、所在行与该行第几列、版面位置、错误、目标内容和必须保留项。
3. 由 Codex 执行返修时，先读取 `$imagegen` 技能；将当前完整原图作为唯一编辑目标，需要时同时提供原始人物和场景参考。
4. 只修改指定格或明确的整图结构问题；锁定其他画格的像素内容、构图、动作、人物、线条、分格线和顺序。
5. 不默认生成独立单格，也不程序化拼接替换格。只有用户明确要求时才允许。
6. 编辑后重新打开完整修订图，先检查目标问题，再检查非目标格是否漂移，最后重跑全部硬性项和质量项。
7. 非目标格被误改时放弃该结果，回到返修前原图重新编辑，不在漂移版本上继续叠加。
8. 整图结构普遍失败时，优先编辑整图；若结构无法受控修复，可依据已确认文字分镜重新生成整张多宫格图。
9. 连续两次受控编辑仍无法锁住其他格或当前工具不支持整图编辑时，如实说明限制并停止；未经用户同意，不改用单格拼接，也不越过故事板确认。

受控编辑提示词：

```text
编辑目标：当前上传的完整多行多列、共{N}格黑白简笔画火柴人故事板原图。
排版规格：{LAYOUT_SPEC}
阅读顺序：{READING_ORDER}

只修改第{PANEL}格，即{位置说明}：
{当前错误与目标画面}

必须保持：
- 其余{N-1}格的像素内容、人物、动作、构图、景别、线条和灰度不变；
- 原有总行数、每行列数、{N}格、已确认的宽面板/跨列面板、画格比例、分格线和阅读顺序不变；
- 非目标格的人物身份、道具、场景、空间关系和累积状态不变；
- 整张图继续保持白底黑线简笔画和火柴人人物，无彩色、写实人体、精细动漫人物、文字、数字、格号、标志和水印。

这是对完整原图的局部受控编辑，不要输出独立单格，不要重新设计其他画格。
```

调用图像编辑后结束当前回复；下一轮再读取修订图并复审。

## 7. 用户修改

用户指出问题时：

1. 记录具体格号和修改要求。
2. 判断是否为局部修改：构图、动作、人物显隐、道具或线条问题可在当前整图修改。
3. 若用户改变剧情目标、人物身份、关键道具、拍摄形式、主要空间关系、实际格数或面板结构，退回文字分镜 Gate 重新确认。
4. 局部修改时执行“完整原图受控编辑”，锁定其他格。
5. 修改后重新打开整图、重跑审查、更新面板映射和修改记录。
6. 返还修订后的完整图并再次等待用户确认。

## 8. 交付与确认

内部审查通过后，只交付：

1. 当前完整故事板图；
2. 实际格数、排版与面板映射表；
3. 本工作段EV/DLG覆盖表；
4. 审查摘要；
5. 修改记录：无修改 / 修改了哪些格及原因；
6. 已知轻微限制；
7. 确认问题。

```text
这版故事板是否确认？如果没问题，请回复“确认故事板”；如果需要调整，请告诉我具体格号和修改内容。确认后我再生成 Seedance 2.5 视频提示词。
```

发出问题后停止。不要把内部“审查通过”当成用户确认，也不要在同一轮提前输出视频提示词。

## 9. 写入视频提示词

只有用户明确确认后才引用故事板：

```text
@图片4：本工作段整张{N}格黑白简笔画火柴人故事板。本段参考SB-01至SB-{N}中与对应时间段有关的构图、人物站位、动作方向和摄影机路径；不参考简笔画火柴人画风、格框、编号、箭头、说明文字及返图中的误生成细节。
```

人物身份、服装、场景材质和色彩仍以对应人物/场景参考素材为准。故事板的黑白简笔画火柴人风格只用于分镜审查，不自动进入最终视频。

不使用故事板的分支不得出现“故事板：无”“未使用故事板”等占位内容。
