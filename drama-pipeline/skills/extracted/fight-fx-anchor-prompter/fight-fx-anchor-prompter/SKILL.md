# 打斗特效提示词生成器 · 流体 × 粒子 × 锚点法 V1.0

> **一句话定位**：用户给一段创意/剧本/主角图 → 你出一张**选择卡**让他一次选完 → 你输出**可直接复制**的打斗特效视频提示词（缺图可自动生成）。
>
> **与同类 skill 的分工**（避免重复劳动，别越界）：
> - `fight-prompt-master` / `seedance-2.5-fight-prompter` 管**动作编排**（谁打谁、招式链、因果交锋、强度档位）。
> - `h3-jackie-chan-fight-director` 管**H3 一打多的调度**。
> - **本 skill 只管「技能特效本身」的物理逻辑**：流体怎么成形、粒子在哪迸溅、技能从哪个锚点冒出来、撞在什么上、反馈成什么样。**换装成"铁匠铺打铁"就贴到 `fight-prompt-master`。**
> - 两者可叠加使用：先由本 skill 定特效，再把特效段落交给动作 skill 嵌进完整编排。

## 一、两条核心方法论（背下来，这是全部底层逻辑）

### 1. 流体做主体，粒子做反馈

| | **流体 Fluid** | **粒子 Particle** |
|---|---|---|
| 本质 | **连续的形态** | 离散的、可崩解的碎片/颗粒 |
| 典型形态 | 能量洪流、能量屏障、光丝、剑气刀气、火焰流体 | 固体碎片、气态烟雾、光点能量 |
| 画面表现 | 连贯、可塑性、动态流动感 | 碎石崩裂、烟尘扩散、光点迸溅 |
| 分工 | **做主体**（大招本体、拖尾主体） | **做反馈**（撞击崩裂、氛围点缀） |

**三条实测结论：**
1. **主体必须带材质词**：写「巨型火龙」→ 模型给**实体火龙**；写「巨型龙形**火焰流体**」→ 才是想要的流体大招。**这一步写错，整条提示词报废。**
2. **拖尾优先用流体**：同场景对比，粒子拖尾和流体拖尾观感差异明显，流体更顺。
3. **想提质感**：流体做主体 + 粒子做点缀（例：「火焰流体」为主体，周围「火焰粒子」点缀）。

### 2. 锚点 + 撞击位置 + 物理反馈（最小三要素）

```
锚点（技能从哪出来） + 撞击位置（打在哪） + 物理反馈（打完变成什么样）
```

- **锚点**：掌心 / 刀剑武器 / 双掌合十 / 地面涌出 / 身后浮现。它**优先级最高**——不写锚点，技能会从人物手里或其他地方**乱冒出来**，稳定性骤降。
- **撞击位置**极灵活：地面 / 城墙 / 树林 / **敌方身体部位** / **敌方护盾** / **敌方技能（法术对轰）** / 兽群。它让"两个人的打斗"产生**连接**。
- **物理反馈最容易忘，但决定打击感**：不写反馈 = 没有打击感。补法：坍塌 + 飞射 + **不规则形状**（规则形状显假）。

**要分清两种"打"：**

| 类型 | 例子 | 反馈写法 |
|---|---|---|
| **撞击位置** | 龙形流体砸向地面/城墙 | 撞击中心 + 碎石/碎砖崩裂（粒子） |
| **接触位置** | 毒雾笼罩古城废墟（覆盖，不是砸） | 接触面出现**被腐蚀脱落**效果 |

### 3. 六要素结构公式（写完整条提示词的骨架）

```
镜头机位 + 流体 + 粒子 + 光效 + 撞击/接触位置 + 物理反馈
```

- **必写**：流体、粒子（缺一个就没有特效）
- **建议写**：撞击/接触位置、物理反馈（决定准确度和打击感）
- **可加**：光效（写好流体+粒子+环境氛围词，色彩效果其实已自动出来）
- **可不写但必须懂**：镜头机位——不写模型也会给合理景别，但**要精确控制就得自己写**

### 4. 通用动作四件套（强推固定搭配）

```
压缩 → 蓄能 → 膨胀 → 吞吐
```

写火焰流体、写强光提质感，通用性极强。**变身/大招类的动作节奏就靠这四个词。**

## 二、第一步永远是出「选择卡」（菜单式，不做开放式追问）

**铁律：**
- 用户**已经明确的**项 → 在卡里标 ✅ 并附他的原话，**不再重复问**。
- 用户**没明确的**项 → 在卡里给出**选项 + ★推荐默认**，让他回编号。
- **禁止**问「你想要什么样的特效？」「你的主角长什么样？」这类开放式问题。**永远给选项。**
- 用户说「按推荐 / 你定 / 随便」→ 直接采用所有 ★ 项，**不再追问第二次**，立刻开工。

**回复方式写清楚**：只回编号，例 `B2 C1+C3 D1 E2 F1+F3`；整组跳过就说「按推荐」。

## 三、工作流（7 步）

```
①判断已知信息 → ②出选择卡 → ③收卡（图片分支） → ④定特效设计表
→ ⑤写提示词（按所选模型封装）→ ⑥自检 → ⑦交付 + 归档
```

1. **判断已知信息**：用户给了什么？创意/剧本/小说/分镜属于哪一级（见 §六 输入分级）？已明确了哪些卡项？
2. **出选择卡**：已明确项标 ✅，其余给选项 + ★推荐。
3. **收卡 → 图片分支**（见 §五）：需要图且用户没图 → 用贞贞工坊生成；用户有图 → 直接进下一步。
4. **定特效设计表**（内部完成，不输出给用户）：
   - 锚点位置 + 技能形态（流体）
   - 撞击/接触位置 + 粒子种类
   - 物理反馈（3-5 项，含"不规则形状"）
   - 动作节奏：压缩→蓄能→膨胀→吞吐
   - 单人可不写景别；**双人/多人必写景别 + 构图 + 距离**
5. **写提示词**：按 §四 的模型格式封装。
6. **自检**：过 §八 清单，**发现问题先改再交付**。
7. **交付 + 归档**：附一句设计说明 + 诊断要点；案例写入 `case-library.md`。

## 四、输出格式规范

### 4.1 三种模型的核心差异（选哪个用哪个）

| | Seedance 2.0 | Seedance 2.5 | MiniMax H3 |
|---|---|---|---|
| 时长 | 8-15s | 4-30s（超长 30-180s） | 10-20s |
| 时间控制 | 连续整秒粗时间段 | **时间戳钉死每一拍** | `[Shot N] At MM:SS.mmm` |
| 语言 | 中文 | 中文 | **英文** |
| 结构 | **11 字段** | **三段式 + 时间戳** | **六段式** |

**详细模板与字段硬规则见 `references/engine-formats.md`。写之前必须读对应的那一节。**

### 4.2 交付形态（每个方案统一）

```
## 方案〔N〕｜〔流体主体〕×〔撞击位置〕·〔一句话看点〕
说明：〔模型〕·〔时长〕·〔画幅〕·〔素材状态〕
自检：✅ 通过（修正：〔本次改了什么，无则写"无"〕）
〔一句设计说明：锚点在哪、撞击在哪、反馈成什么样〕

```text
〔可直接复制的完整视频提示词〕
```
```

**提示词本身必须是「可直接复制粘贴」的一整块**，不带任何解释性文字、不带 markdown 语法、不带「以下为提示词」之类的话。

### 4.3 特效段落写作规范（本 skill 的核心产出）

不管哪个模型，**特效部分必须写满这 5 句**：

| # | 必写句 | 反例（禁） | 正例 |
|---|---|---|---|
| 1 | **主体形态** | 「巨型火龙」 | 「巨型龙形**火焰流体**」 |
| 2 | **锚点位置** | 「释放技能」 | 「自**掌中心**凝出雷球」「技能自**身后**浮现」 |
| 3 | **撞击/接触位置** | 「打出去」 | 「撞击中心为**城墙**」 |
| 4 | **粒子迸溅** | 「很炫酷」 | 「迸溅**红色火星粒子**与**黑烟粒子**」 |
| 5 | **物理反馈** | 「被击飞」 | 「城墙**大面积碎砖崩裂扬尘**，**形状不规则**」 |

**另有两条距离参数必须明写**（踩过的坑）：**高度/方位要写**——「悬于**百米高空画面左上方**」+「**仰视视角**」，不写就翻车（技能位置太低）。

### 4.4 字数与篇幅

- 单条提示词 300-800 字（特效为主时 300-500 字足够）
- 不堆形容词。**每个强度词都要能落到具体载体 + 接触点物理现象 + 环境后果**

## 五、图片资产分支（缺图时）

### 5.1 三条路，让用户挑（写在卡里，别问）

| 路 | 做法 | 适用 |
|---|---|---|
| **1. 用户上传** | 直接用 `@图片1` | 已有立绘/参考图 |
| **2. 贞贞工坊自动生成** | 跑 `scripts/gen_image.py` | 没图、要快、要统一 |
| **3. 纯文字不用图** | 特效类**纯文本就能出效果**，不上传任何资产 | 只要特效/巨兽形态 |

> 教程实测：**纯文本就能达到演示效果**，不必一开始就上传参考图。要统一形象（固定的龙 / 加人物）再用参考内容。

### 5.2 用贞贞工坊生成（默认走这条）

**渠道口径（铁律，不许换通道）：**
- 端点：`POST https://api.seedance.nz/v1/image/generations`（**路径是单数 `image`**，写复数 404）
- 默认模型：`zhenzhen-image-g-v2.5-lowprice`（带 `size` + `resolution` 两个顶层入参）
- 档位：**测试 1k（¥0.0446）· 默认 2k（¥0.105）· 正式大场景 4k（¥0.1575）**
- 凭证：四级自动读取（`--api-key` > 环境变量 > 项目 `.env` > `~/.workbuddy/credentials/mv-auto-pipeline/keys.env`）——**永远不问用户要 key**

**调用命令（自己拼，别让用户跑）：**

```bash
# PY = 你的 Python 解释器路径（自行替换；用 WorkBuddy 托管版本的形如
#      <runtime>/binaries/python/envs/default/Scripts/python.exe）
PY="<python 解释器路径>"
env -u https_proxy -u HTTPS_PROXY -u http_proxy -u HTTP_PROXY "$PY" \
  ~/.workbuddy/skills/fight-fx-anchor-prompter/scripts/gen_image.py \
  --prompt-file char.txt --output ./fx_assets/char.png --size 3:4 --resolution 2k
```

- 主角图 `--size 3:4`（半身正面纯白底）· 场景图 `--size 16:9` · 道具 `--size 1:1`
- 批量：`--batch assets.json --output-dir ./fx_assets`（支持断点续跑）
- 出图提示词模板见 `references/image-prompts.md`（含**四视图转身参考**写法——人物与背景割裂、质感不行，往往是缺三视图）

**排障（都踩过）：**
- **HTTP 403 先挖 body**：`insufficient_user_quota` = **额度不足** → 告诉用户充值，**不许换通道**。
- 一批图前面成功、后面全 403 → 额度见底，不是限流。
- 连接重置 10054 / `EOF in violation` / Cloudflare 1010 → **先怀疑代理**，命令前加 `env -u https_proxy -u HTTPS_PROXY -u http_proxy -u HTTP_PROXY`。
- 单张耗时 43s~253s 波动大，轮询给足（脚本已内置 5s × 90）。

**生成后必须用 `present_files` 把图给用户看**，再继续写提示词。

### 5.3 参考图怎么进提示词

- Seedance：`@图片1` = 主角、`@图片2` = 对手、`@图片3` = 场景
- H3：`<Subject 1> whose appearance comes from <Picture 1>`（**不给图片单独开一行**）
- **最小资产只要人物主视图**；要质感再补场景图 + 三视图

## 六、输入分级（怎么处理用户给的文字）

| 级别 | 输入 | 处理策略 |
|---|---|---|
| **L1 创意** | 一句话 | 补全题材/场景/角色/2-3 个特效节点 |
| **L2 剧本** | 有角色+对抗 | 直接生成，补外观锚点、武器、场景、特效链、结尾 |
| **L3 小说** | 长叙事中的打斗段 | **抽骨架**（胜负与转折）→ **去修辞**（删"气势如虹/天地变色"等不可拍内容）→ **建奇观**（选 2-3 个最具视觉冲击的画面做节点）。**不逐句翻译** |
| **L4 锁定分镜** | 带时间轴/动作链 | 剧情结果、顺序、视觉锚点、出口为**硬约束**，只补衔接和物理反馈 |

> **原作用户文字绝不删改**：台词、动作结果、角色名一律保留原样。

## 七、失败诊断（单变量排错）

用户拿翻车结果回来 → **每轮只改一类变量**，改完复测再定下一步。

| 症状 | 真因 | 修法 |
|---|---|---|
| 技能位置太低/贴地 | 没写高度与视角 | 补「悬于**百米高空画面左上方**」+「**仰视视角**」 |
| 出来的是实体（火龙/龙）而非流体 | 主体没带材质词 | 「巨型火龙」→「巨型龙形**火焰流体**」 |
| 技能从人物身前乱冒 | 锚点没写或位置写错 | 明确「锚点锁定**掌心**」「自**身后**浮现」 |
| 没有打击感 | 缺物理反馈 | 补「坍塌 + 碎石飞射 + **不规则形状**」 |
| 特效很假/像贴图 | 缺光效与环境氛围词 | 补体积光 / 环境漫射 / 自发光（可加英文 `volumetric fog`） |
| 双人镜头"低智"、两人没距离感 | 没写景别构图 | 补「两人位于画面两端相距百米」+「对角构图：一人在左下地面，一人在右上角」 |
| 人物与背景割裂、细节差 | 缺三视图 | 补四视图转身参考图 |
| 蓄力幅度不够 | 动作没写起手 | 补「抬手再向前伸出」 |
| 语病导致的偏差 | 用词不当 | 「不规则雷球」→「**不规则的形状**」 |
| 偶发异常（模型抽风） | **不是提示词问题** | **直接再生成一遍**，别改提示词 |

> **判据：失败是提示词问题，不是模型问题**——先查这 10 条，再考虑重生成。

## 八、内容边界与自检

### 边界
- 不复制外部提示词的完整句子、固定动作链；不调用知名影视/动漫/游戏角色
- 不用空泛强度词（「毁天灭地」）替代可见物理现象
- **特效不遮主体**：粒子只沿武器/碰撞点/攻击轨迹，不铺满屏幕盖住身体轮廓
- 默认无字幕、无水印、不加用户未要求的旁白/BGM
- 首次接触打斗特效类需求 → **先出选择卡**，不擅自开工

### 自检清单（过不了不许交付）
```
[ ] 选择卡已出且用户已确认（或有明确"按推荐"）
[ ] 流体主体带材质词（不是实体名词）
[ ] 锚点位置写清楚了（掌心/武器/地面/身后）
[ ] 撞击或接触位置明确（并区分了"撞击"还是"覆盖接触"）
[ ] 物理反馈 ≥3 项，且含「不规则形状」
[ ] 高度/方位明写（需要时）+ 视角写成
[ ] 双人/多人：景别 + 构图 + 距离都写了
[ ] 光效/环境氛围词有（可用英文关键词补强）
[ ] 特效不遮主体，粒子位置受约束
[ ] 提示词是可直接复制的一整块，无解释性文字
[ ] 按所选模型用了正确格式（2.0=11字段 / 2.5=时间戳 / H3=英文六段）
[ ] 结尾干净（不写"缓缓收势/光芒渐熄/定格摆姿势"）
[ ] 若生成图：已 present_files 给用户看
[ ] 案例已写入 case-library.md
```
